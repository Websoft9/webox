## 技术实现

### 1. 架构设计
采用分层架构设计：
- **Controller层**: 处理HTTP请求和响应
- **Service层**: 业务逻辑处理
- **Repository层**: 数据访问操作
- **DTO层**: 数据传输对象

### 2. 核心文件

#### 新增文件
- `internal/dto/user_dto.go` - 用户相关的数据传输对象
- `docs/USER_MANAGEMENT_API.md` - API接口文档
- `test_user_api.ps1` - PowerShell测试脚本
- `test_user_api.sh` - Bash测试脚本

#### 更新文件
- `internal/controller/user_controller.go` - 用户控制器（完全重写）
- `internal/service/user_service.go` - 用户服务（扩展功能）
- `internal/repository/user_repository.go` - 用户仓库（扩展功能）
- `internal/router/router.go` - 路由配置（新增用户管理路由）

### 3. API接口列表

| 方法   | 路径                    | 功能       | 权限要求 |
|--------|-------------------------|------------|----------|
| POST   | /api/v1/auth/register   | 用户注册   | 无       |
| POST   | /api/v1/auth/login      | 用户登录   | 无       |
| GET    | /api/v1/users/profile   | 获取资料   | 用户     |
| GET    | /api/v1/users           | 用户列表   | 用户     |
| POST   | /api/v1/users           | 创建用户   | 管理员   |
| GET    | /api/v1/users/{id}      | 用户详情   | 用户     |
| PUT    | /api/v1/users/{id}      | 更新用户   | 管理员   |
| DELETE | /api/v1/users/{id}      | 删除用户   | 管理员   |
| PUT    | /api/v1/users/{id}/password | 修改密码 | 用户/管理员 |

### 4. 数据模型

基于已有的User模型，支持以下字段：
- 基础信息：用户名、邮箱、昵称、头像、手机号
- 个人信息：性别、个性签名、时区、语言
- 系统信息：状态、创建时间、更新时间、最后登录信息
- 关联信息：用户组、角色权限
