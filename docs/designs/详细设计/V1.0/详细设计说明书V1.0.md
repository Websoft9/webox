## 1. 引言

本文档为 **Websoft9架构升级** 的详细设计文档，本文档的编写目的在于明确 **Websoft9架构升级** 需求的开发途径以及应用方法，通过此文档，为此 **Websoft9架构升级** 需求的维护提供清晰、详细的设计，为下阶段开发工作的开展起到指导作用。

本文档的预期读者是 **Websoft9架构升级** 需求相关的业务人员、开发人员以及系统运维人员。

### 1.1 名词定义

| 名词                  | 说明                                                                                                                                           |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `平台`                | 本文档所述“平台”、“`Websoft9平台`”均指`Websoft9平台`。                                                                                         |
| `CI/CD`               | 持续集成（Continuous Integration, CI）与持续交付/部署（Continuous Delivery/Deployment, CD）。 通过自动化流程和工具简化并加快软件开发生命周期。 |
| `Websoft9 Mobile App` | `Websoft9平台`提供的移动端客户端，提供监控分析、便捷操作和基本查询功能。                                                                       |
| `Websoft9 Agent`      | `Websoft9平台`提供的服务器客户端，提供服务端任务执行、监控采集等功能。                                                                         |
| `应用`                | `Websoft9平台`应用商店提供的应用，支持用户按需选择进行应用部署、发布、更新等操作。                                                             |
| `纳管`                | 已安装`Websoft9 Agent`的服务器和部署的应用，可以被`Websoft9平台`直接管理。                                                                     |
| `发布`                | 指将已经部署的应用发布为互联网可访问的服务，例如：个人网站。本文档所述`应用发布`为将应用通过`Websoft9平台`提供的应用网关服务进行发布。         |
| `应用部署模版`        | 指容器模版（Dockerfile/Compose config）和工作流模版（workflow），用于描述如何将应用部署的配置信息。                                            |
| `SaaS`                | 软件即服务，本文档所述指`Websoft9平台`以`云服务平台`方式为客户提供应用托管服务。                                                               |
| `PaaS`                | 平台即服务，本文档所述指`Websoft9平台`以`私有化平台`方式为客户提供应用托管服务。                                                               |
| `RBAC`                | 基于角色的访问控制，一种通用的访问控制模型，基于用户角色进行权限管理，用户角色与权限之间是多对多的关系。                                       |

## 2. 平台功能设计

### 2.1 监控面板

`监控面板`提供平台全局的监控分析能力，包括监控指标的图表展示，以及各服务器及应用服务状态的查询。

#### 2.1.2 全局概览

`全局概览`为平台全局状态的总览，直观反应平台全局既有的资源使用情况，以及各容器或非容器应用运行状态。

![监控面板主页](../../原型设计/websoft9_webservice_ui/监控面板主页.png)

- **功能描述**

1. 全局概览指标

以数值的形式进行展示全局关键指标，查询条件：时间范围，默认为近30天。服务器和应用的状态字典参考附录《6.2 状态字典定义》。

| 监控指标   | 示例 | 描述                           | 统计规则                    |
| ---------- | ---- | ------------------------------ | --------------------------- |
| `应用实例` | 0/1  | 展示已部署安装的应用实例数量。 | SUM(应用实例数量)           |
| `运行中`   | 0/1  | 展示运行中的应用实例数量。     | SUM(应用实例状态为运行中)   |
| `已停止`   | 0/1  | 展示已停止的应用实例数量。     | SUM(应用实例状态为非运行中) |
| `服务器`   | 0/1  | 展示已纳管的服务器数量。       | SUM(服务器数量)             |
| `异常告警` | 0/1  | 展示已发生的异常告警数量。     | SUM(监控告警数量)           |
| `调度任务` | 0/1  | 展示已调度的工作流任务数量。   | SUM(工作流任务状态为已发布) |

| 查询条件 | 示例 | 描述                                         |
| -------- | ---- | -------------------------------------------- |
| 时间范围 | 1/30 | 日期选项，选择一个日期范围的天数，最大30天。 |

2. 应用概览
   - 【应用资源使用分布图】折线图，展示TOP5（由高到低）的应用，按照应用实例的维度，统计近24小时的内存、CPU的使用占比。
   - 【应用监控趋势图】折线图，展示时间范围内的应用监控指标趋势，查询条件：应用名称，时间范围，指标。

| 查询条件 | 示例             | 描述                                            |
| -------- | ---------------- | ----------------------------------------------- |
| 应用名称 | application name | 单选下拉选项，展示所有应用的名称列表。          |
| 时间范围 | 1/30             | 日期选项，选择一个日期范围的天数，最大30天。    |
| 指标     | 内存             | 单选下拉选项，展示可选的监控指标，参考附录6.1。 |

3. 服务器概览

   - 【服务器资源使用分布图】折线图，展示TOP5（由高到低）的服务器，按照服务器的维度，统计近24小时的内存、CPU、磁盘空间的使用占比。
   - 【服务器监控趋势图】折线图，展示时间范围内的服务器监控指标趋势，查询条件：服务器名称，时间范围，指标。

| 查询条件   | 示例        | 描述                                            |
| ---------- | ----------- | ----------------------------------------------- |
| 服务器名称 | server name | 单选下拉选项，展示所有服务器的名称列表。        |
| 时间范围   | 1/30        | 日期选项，选择一个日期范围的天数，最大30天。    |
| 指标       | 内存        | 单选下拉选项，展示可选的监控指标，参考附录6.1。 |

#### 2.1.3 服务器监控看板

`服务器监控看板`提供服务器状态的监控分析，包括服务器各项指标的图表展示及查询。

![服务器监控看板](../../原型设计/websoft9_webservice_ui/服务器监控看板.png)

- **功能描述**

1. 服务器监控指标

以数值的形式进行展示全局服务器关键指标，查询条件：时间范围，默认为近30天。

| 监控指标   | 示例 | 描述                                     | 统计规则                  |
| ---------- | ---- | ---------------------------------------- | ------------------------- |
| `服务器`   | 0/1  | 展示已纳管的服务器数量。                 | SUM(服务器数量)           |
| `已停止`   | 0/1  | 展示已停止的服务器数量。                 | SUM(服务器状态为非运行中) |
| `应用实例` | 0/1  | 展示已部署安装的应用实例数量。           | SUM(应用实例数量)         |
| `存储空间` | 5GB  | 展示已纳管的服务器磁盘空间用量。         | SUM(服务器磁盘空间用量)   |
| `异常告警` | 0/1  | 展示已发生的服务器异常告警数量。         | SUM(服务器监控告警数量)   |
| `系统服务` | 0/1  | 展示已纳管的服务器运行中的系统服务数量。 | SUM(系统服务状态为运行中) |

| 查询条件 | 示例 | 描述                                         |
| -------- | ---- | -------------------------------------------- |
| 时间范围 | 1/30 | 日期选项，选择一个日期范围的天数，最大30天。 |

2. 服务器列表

按照服务器名称排序，以列表方式展示已接入纳管的服务器，展示信息：服务器图标、服务器名称、服务器状态、服务器启动时长（XXX天XXX时）、服务器内外网IP、所属资源组名称，用户可以点击【管理】按钮跳转至服务器管理界面，点击服务器名称展示相应的【服务器信息】和【服务器监控图表】。

3. 服务器信息

当用户点击选择一个服务器时，展示服务器的基本信息：服务器图标、服务器状态、服务器名称、操作系统名称、内核版本、服务器备注、服务器安装日期（接入纳管的日期）、服务器运行时间（XXX天XXX时）、所属资源组名称，运行中的应用实例数量、CPU参数、内存参数、磁盘存储空间参数（已使用/磁盘空间），网络参数（内外网IP）。

4. 服务器监控图表

当用户点击选择一个服务器时，分别展示监控指标的趋势图和监控日志列表。

- 【内存使用率】折线图，展示时间范围内的内存使用量趋势，查询条件：时间范围。
- 【CPU】折线图，展示时间范围内的CPU负载、使用趋势，查询条件：时间范围，指标（LOAD/USED）。
- 【存储空间】折线图，展示时间段内的磁盘空间使用趋势，查询条件：时间范围。
- 【网络】折线图，展示时间段内的网络IO趋势，查询条件：时间范围。
- 【监控日志】文本列表，默认按照时间由近到远排序，展示时间段内的日志明细内容，查询条件：日志类别，时间范围。

### 2.2 应用商店

`应用商店`是平台提供的开放应用服务市场，提供官方维护的可信安全的应用源，同时支持`应用容器模版`部署、`自定义应用容器模版`部署、`自定义软件包`安装等功能，用户可下载、安装、卸载、升级、查看应用服务详情。

#### 2.2.1 应用快捷导航

`应用快捷导航`提供对所有用户已部署、已发布的应用的快速访问入口，方便用户进行直接访问使用。

![应用快捷导航](../../原型设计/websoft9_webservice_ui/应用快捷导航.png)

- **功能描述**

1. 应用部署模版的技术规范

统一采用`Docker compose`部署模版，并约定标准的部署配置参数，未来只需要调整配置参数值，除自定义模版部署的参数微调以外，避免每一个应用存在不同的部署模版、导致管理混乱，示例：

```yaml
version: "3.8"

services:
  application_service:
    image: nginx:1.25
    deploy:
      replicas: 1
      restart_policy:
        condition: on-failure
        delay: 5s
        max_attempts: 3
        window: 120s
      resources:
        limits:
          cpus: "0.50"
          memory: 512M
        reservations:
          cpus: "0.25"
          memory: 128M
      placement:
        constraints: [node.role == worker]
    ports:
      - "80:80"
    environment:
      - NGINX_HOST=localhost
      - NGINX_PORT=80
    volumes:
      - app_volumes_data:/home/websoft9/application/volumes/nginx/
    networks:
      - websoft9_app_cluster

volumes:
  app_volumes_data:

networks:
  websoft9_app_cluster:
    driver: overlay
```

>
> **技术规范**
>
> - websoft9的应用部署模版包含六个部分组成：镜像配置、发布配置（Docker swarm）、环境变量、存储卷配置、网络配置、健康检查策略。
> - 对以下配置参数进行规范和限制：
>   - `version` 版本号，且尽可能保持使用统一的版本以兼容`Docker compose`及`Docker swarm`。
>   - `restart_policy` 重启策略，必须显示声明容器应用的重启策略。
>   - `resources` 资源分配，必须显示声明容器应用的资源分配及限制。
>   - `placement` 部署位置，默认情况下应用部署至worker节点，仅单节点时部署至manager节点。
>   - `environment` 环境变量，参考【应用部署模版的参数化和解析】。
>
>
> **命名规范**
>
> - 遵循`Docker Compose`的命名规范和约束。
> - 对平台提供的基础配置（存储卷、网络、服务），均以websoft9作为前缀命名以区别同名的情况，例如：websoft9_app_cluster。
>

2. 应用部署模版的参数化和解析

`Docker compose`的部署模版文件支持参数化，对需要进行动态配置的参数可以使用`变量表达式`，在应用部署向导中将自动解析`变量表达式`，生成对应的表单选项供用户填写，例如：

```yaml
version: "3.8"

services:
  mysql:
    image: mysql:8.0
    container_name: mysql
    restart: always
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD:-123456}
      MYSQL_DATABASE: ${MYSQL_DATABASE:-wp_db}
      MYSQL_USER: ${MYSQL_USER:-root}
      MYSQL_PASSWORD: ${MYSQL_PASSWORD}
    ports:
      - "3306:3306"
    volumes:
      - mysql_data:/var/lib/mysql

volumes:
  mysql_data:
```

页面表单示例：

![config_form_sample](images/config_form_sample.png)

>
> **变量作用域**
>
> - 平台密钥管理中已授权可使用的密钥信息。
> - 应用部署向导中用户填写的信息。
> - 系统环境变量。
>
> **变量解析**
>
> - 平台实现compose文件中变量表达式的解析和处理，前端实现动态表单的生成和交互。
>
> **技术规范**
>
> - 遵循`Docker Compose`的变量命名规范和约束。
> - 不使用`compose --env-file`选项进行变量文件指定，将`.env`文件名称与`compose`文件名称保持一致并存在同一级目录下。
>
> ```ini
>  MYSQL_ROOT_PASSWORD=your_root_password
>  MYSQL_DATABASE=your_db_name
>  MYSQL_USER=your_user
>  MYSQL_PASSWORD=your_password
> ```
>
> **参考文档**
>
> - <https://docs.docker.com/compose/how-tos/environment-variables/>
> - <https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/>
>

2. 工作流组件

**`工作流组件`是工作流中的执行单元**，为平台预置的常用组件，未来也可以提供用户自定义组件。用户可以在工作流编排时使用、删除、配置工作流组件。

- 组件的参数化和计算：

  组件支持参数化配置，支持使用变量表达式，变量表达式的解释和计算使用golang表达式框架实现。参数的作用域及优先级如下：

  - **全局参数**：全局参数作用域为平台级别，所有工作流中任意组件均可以使用，全局参数包含来自平台【密钥管理】授权可使用的信息、平台预定义参数、字典，例如：环境变量等。
  - **工作流参数**：工作流参数作用域为工作流级别，仅当前工作流中任意组件可以使用，工作流参数包含工作流中预定义的参数，例如：目录名称、版本号等。
  - **输入/输出参数**：输入/输出参数作用域为组件级别，仅定义参数的组件上下游之间可以使用，不允许跨组件引用。

- 每一个组件都由三个部分组成：

  - 输入参数：输入参数为上游组件的输出参数，包括参数名称、参数描述、参数类型、参数值。
  - 执行逻辑：组件的具体执行逻辑。
  - 输出参数：组件的执行结果，为可选项，包括参数名称、参数描述、参数类型、参数默认值。

- 工作流组件列表：

  | 组件名称     | 分类       | 描述                                                                                                                                   |
  | ------------ | ---------- | -------------------------------------------------------------------------------------------------------------------------------------- |
  | `判断组件`   | 控制组件   | 支持对工作流节点执行的结果进行判断（YES/NO），当逻辑条件成立时则继续执行，否则终止执行。                                               |
  | `分支组件`   | 控制组件   | 支持对工作流节点执行的结果进行分支判断，当某一分支的逻辑条件成立时则继续执行分支流程，否则终止分支流程执行。                           |
  | `接口调用`   | 应用组件   | 支持调用第三方API接口，支持HTTP/HTTPS协议，GET/POST等请求。                                                                            |
  | `发送邮件`   | 应用组件   | 支持发送邮件，可以使用预定义的邮件模版内容，注意：禁止使用JS脚本。                                                                     |
  | `发送短信`   | 应用组件   | 支持发送短信，可以使用预定义的短信模版内容，注意：短信发送、短信模版内容的管理依赖云厂商提供的短信服务。                               |
  | `命令行`     | 应用组件   | 支持在目标服务器上执行命令行，并返回执行结果。                                                                                         |
  | `脚本`       | 应用组件   | 支持使用脚本代码实现复杂业务逻辑计算，例如：Groovy、JS。注意：禁止特定、非安全的API使用，例如：读取操作系统文件目录、执行Shell命令等。 |
  | `文件下载`   | 应用组件   | 支持从工作空间、目标服务器下载文件至本地。                                                                                             |
  | `文件上传`   | 应用组件   | 支持将本地文件上传至工作空间、目标服务器。                                                                                             |
  | `应用发布`   | 应用组件   | 支持将已部署的应用快速发布至平台应用网关                                                                                               |
  | `S3存储`     | 云服务组件 | 支持接入S3存储服务，实现文件的上传、下载、删除等操作。                                                                                 |
  | `云资源管理` | 云服务组件 | 支持接入云服务资源管理，实现云资源的快捷操作。                                                                                         |

  >
  > **组件分类**
  >
  > - 控制组件：这一类型的组件可以实现对工作流执行状态、顺序的控制。
  > - 应用组件：这一类型的组件可以实现不同场景的具体业务实现，例如：执行某一个命令行代码片段。
  > - 云服务组件：这一类型的组件实现对云资源的操作，例如：创建ECS实例、上传文件到OSS。
  >

- **业务流程**

资源看板数据更新流程：

1. 系统定时任务每5分钟执行一次数据采集。
2. 从各个数据源（监控系统、应用管理、服务器管理）获取最新数据。
3. 计算各项统计指标并更新缓存。
4. 前端页面通过WebSocket或定时轮询获取最新数据。
5. 用户访问资源看板时直接从缓存获取数据展示。

- **技术实现**

1. 【数据聚合】使用Redis缓存预计算的统计数据，避免实时查询数据库造成性能问题。
2. 【图表数据】使用时间序列数据库（InfluxDB）存储历史趋势数据，支持高效的时间范围查询。
3. 【实时更新】通过WebSocket推送数据变更通知，实现页面数据的实时更新。

- 【打包下载】支持将证书相关文件打包下载。

4. 验证证书的有效期和域名。
5. 将证书文件保存到指定目录。
6. 更新证书数据库记录。
7. 自动部署到应用网关。

7. 发送续期结果通知。

3. 【TOTP双因子认证实现】

实现基于时间的一次性密码认证：

```go
// TOTP密钥生成
func generateTOTPSecret(username string) (*otp.Key, error) {
    return totp.Generate(totp.GenerateOpts{
        Issuer:      "Websoft9",
        AccountName: username,
        SecretSize:  32,
    })
}

// TOTP验证
func validateTOTP(secret, code string) bool {
    return totp.Validate(code, secret)
}

// 双因子认证中间件
func requireTwoFactor(next http.HandlerFunc) http.HandlerFunc {
    return func(w http.ResponseWriter, r *http.Request) {
        user := getCurrentUser(r)

        if user.TwoFactorEnabled && !isTwoFactorVerified(r) {
            http.Redirect(w, r, "/auth/2fa", http.StatusFound)
            return
        }

        next(w, r)
    }
}
```

  - 依赖检查：检查系统依赖是否满足新版本要求。
  - 网络检查：验证网络连接和下载速度。
  - 权限检查：确保有足够的权限执行更新操作。

- 【数据备份】
  - 自动备份：更新前自动备份数据库和配置文件。
  - 备份验证：验证备份文件的完整性。
  - 备份存储：将备份文件存储到安全位置。
  - 恢复准备：准备数据恢复方案。

3. 【更新执行】

支持平台的在线更新：

- 【更新下载】
  - 增量下载：仅下载变更的部分，减少下载时间。
  - 断点续传：支持下载中断后的断点续传。
  - 校验验证：下载完成后验证文件完整性。
  - 进度显示：实时显示下载进度和剩余时间。

- 【服务更新】
  - 滚动更新：逐个更新服务实例，确保服务不中断。
  - 健康检查：更新后检查服务健康状态。
  - 回滚机制：更新失败时自动回滚到上一版本。
  - 状态监控：实时监控更新过程中的系统状态。

4. 【更新管理】

支持更新过程的管理和监控：

- 【更新历史】
  - 更新记录：记录所有更新操作的详细信息。
  - 版本历史：展示平台的版本变更历史。
  - 更新日志：显示每个版本的更新内容和修复问题。
  - 回滚记录：记录回滚操作的历史。

- 【更新策略】
  - 自动更新：支持配置自动更新策略。
  - 定时更新：设置定时更新的时间窗口。
  - 手动更新：支持管理员手动触发更新。
  - 更新通知：更新完成后发送通知给管理员。

5. 【回滚功能】

支持更新失败时的回滚操作：

- 【自动回滚】

  - 管理员可以手动触发回滚操作。

  - 回滚前进行数据备份。

- 【更新进度】更新过程中的进度通知。

- 【维护通知】更新期间的系统维护通知。

- 【调用方式】
  - HTTP POST请求到指定URL。
  - 请求头包含认证信息。
  - 请求体包含触发参数。
  - 支持JSON格式数据。

- 【调用示例】

```bash
curl -X POST \
  https://websoft9.example.com/webhook/deploy-trigger \
  -H 'Authorization: Bearer your-token' \
  -H 'Content-Type: application/json' \
  -d '{
    "workflow_id": "workflow_001",
    "parameters": {
      "version": "1.0.0",
      "environment": "production"
    }
  }'
```

## 3. 非功能需求设计

### 3.1 性能需求设计

#### 响应时间要求

- **客户端响应时间**

客户端是指用户浏览器、手机端APP。访问请求的响应时间要求为 **从客户端发起网络请求到服务端（接口服务层 API Services）返回响应的时间，要求小于1秒（1000ms）**。

- **API接口响应时间**

| 接口类型     | 响应时间要求 | 描述                         |
| ------------ | ------------ | ---------------------------- |
| 查询类接口   | < 500ms      | 数据查询、列表展示等读操作   |
| 操作类接口   | < 1000ms     | 数据创建、更新、删除等写操作 |
| 文件上传接口 | < 5000ms     | 文件上传、导入等操作         |
| 批量操作接口 | < 10000ms    | 批量数据处理操作             |

- **数据库查询性能**

| 查询类型 | 性能要求 | 优化措施                  |
| -------- | -------- | ------------------------- |
| 单表查询 | < 100ms  | 建立适当索引              |
| 关联查询 | < 300ms  | 优化SQL语句，建立联合索引 |
| 聚合查询 | < 500ms  | 使用缓存，预计算统计数据  |
| 全文搜索 | < 1000ms | 使用搜索引擎或全文索引    |

#### 并发性能要求

- **用户并发支持**

| 用户规模 | 并发用户数 | 系统配置要求 |
| -------- | ---------- | ------------ |
| 小型部署 | 100        | 2核8GB内存   |
| 中型部署 | 500        | 4核18GB内存  |
| 大型部署 | 1000+      | 8核32GB内存  |

- **API并发处理能力**

系统应支持每秒处理1000个API请求，通过以下技术实现：

- 使用连接池管理数据库连接。
- 实现API请求的异步处理。
- 使用Redis缓存减少数据库访问。
- 实现负载均衡分散请求压力。

#### 资源使用优化

- **内存使用优化**
  - 实现对象池管理，减少内存分配和回收。
  - 使用流式处理大数据量操作。
  - 定期清理缓存和临时数据。
  - 监控内存使用情况，防止内存泄漏。

- **CPU使用优化**
  - 使用协程池处理并发任务。
  - 实现任务队列避免CPU峰值。
  - 优化算法复杂度，减少计算开销。
  - 使用缓存减少重复计算。

- **服务冗余设计**
  - 关键服务采用多实例部署。
