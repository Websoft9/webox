## 1 引言

本文档为 **Websoft9** 中"项目空间"功能的详细设计文档，它以 BMAD-METHOD 框架作为指导范式，基于 PRD、Epic/Feature 和架构文档创建用户故事，为下一步开发任务准备严格的标准。

## 2 功能概述

### 2.1 功能定位

`项目空间` 是基于 Git 的供项目和个人使用的文件管理系统，支持用户按需进行文件的上传、下载、创建、修改、删除等操作，为项目提供统一的文件存储和版本控制能力。

### 2.2 核心特性

- **双重空间类型**：支持项目空间（团队共享）和个人空间（私人使用）
- **版本控制**：基于Git的文件版本管理，支持特定文件类型的版本追踪
- **权限管理**：细粒度的文件和文件夹权限控制
- **安全保护**：文件回收站机制，防止误删除
- **高效搜索**：支持文件名和内容的全文搜索
- **存储配额**：灵活的存储空间配额管理

### 2.3 技术架构

- **存储引擎**：基于Git的文件存储和版本控制
- **权限模型**：RBAC角色权限控制
- **搜索引擎**：支持全文搜索的索引机制
- **缓存策略**：Redis缓存提升访问性能

| **工作流Feature** | 弱依赖 | 工作流文件和模板的存储管理 | 工作流文件管理功能 |

### 3.5 开发优先级建议

**Phase 0: 基础服务准备（开发前置条件）**
- 认证服务（用户身份验证）
- 权限服务（基础权限验证）
- 审计服务（操作日志记录）
- 数据库服务（元数据存储）

**Phase 1: 核心功能开发**
- 项目空间基础功能开发
- 与认证、权限服务的集成
- 基础文件操作功能

**Phase 2: Feature间集成**
- 与用户管理Feature的数据集成
- 与项目管理Feature的关联
- 工作流和应用管理的文件存储集成

**Phase 3: 高级功能开发**
- 搜索引擎集成
- 监控服务集成
- 性能优化和缓存策略

### 3.6 风险评估与应对

**高风险依赖：**
- **认证服务不可用**：项目空间完全无法使用
  - 应对：实现认证服务的高可用部署，设计降级策略
- **权限服务故障**：可能导致权限控制失效
  - 应对：实现权限缓存机制，设置默认安全策略

**中风险依赖：**
- **用户管理Feature变更**：可能影响用户信息获取
  - 应对：定义稳定的数据接口，使用数据适配层
- **项目管理Feature调整**：可能影响项目关联逻辑
  - 应对：通过事件驱动架构解耦，避免直接依赖

**低风险依赖：**
- **通知服务异常**：仅影响通知功能，不影响核心业务
  - 应对：异步处理，允许通知失败
- **搜索引擎故障**：可降级到基础搜索功能
  - 应对：实现多层搜索策略，基础功能可用

## 4 Business（业务目标与用户故事）

### 4.1 业务目标概述

- 统一项目内外文件管理，提供版本控制与权限管理
- 减少重复配置与资料丢失风险
- 支持团队协作的文件共享与版本追踪

### 4.2 核心用户故事拆分

1. **US001 - 空间管理**
   - 作为项目管理员，我希望创建/删除项目空间，以便管理项目文件归属
   - 作为普通用户，我希望拥有个人私有空间保存私密文件
   - 作为管理员，我希望配置空间存储配额，以便控制资源使用

2. **US002 - 文件操作**
   - 作为项目成员，我希望上传/下载/移动文件，保证协作效率
   - 作为用户，我希望批量操作文件，提高工作效率
   - 作为用户，我希望通过拖拽方式上传文件，提升使用体验

3. **US003 - 版本控制**
   - 作为开发者，我希望查看文件版本历史，以便追溯变更
   - 作为用户，我希望回滚到历史版本，确保数据安全
   - 作为审计员，我希望查看文件操作日志，便于审计追踪

4. **US004 - 权限管理**
   - 作为项目管理员，我希望设置文件夹权限，控制成员访问范围
   - 作为用户，我希望分享文件给特定成员，支持协作
   - 作为管理员，我希望无法查看个人空间内容，保护隐私

5. **US005 - 搜索与导航**
   - 作为用户，我希望快速搜索文件，提高查找效率
   - 作为用户，我希望使用面包屑导航，方便目录跳转
   - 作为用户，我希望切换不同视图方式，适应不同使用场景

## 5 Module（模块拆分与职责）

### 5.1 模块架构设计

```
项目空间 Feature
├── 空间管理模块（Space Management）
├── 文件操作模块（File Operations）  
├── 版本控制模块（Version Control）
├── 权限管理模块（Permission Management）
├── 搜索导航模块（Search & Navigation）
└── 存储管理模块（Storage Management）
```

### 5.2 模块功能映射

| 模块名称 | 核心功能 | 业务场景 | 技术实现要点 |
|----------|----------|----------|-------------|
| 空间管理模块 | 空间创建/删除/迁移/配额管理 | 项目初始化、用户注册、空间维护 | UUID标识、存储配额、Git仓库管理 |
| 文件操作模块 | 文件CRUD、批量操作、回收站 | 日常文件管理、团队协作 | 拖拽上传、批量处理、软删除机制 |
| 版本控制模块 | 版本记录、对比、回滚 | 代码管理、文档版本追踪 | Git集成、差异对比、白名单策略 |
| 权限管理模块 | 细粒度权限控制 | 团队协作、数据安全 | RBAC模型、继承机制、权限缓存 |
| 搜索导航模块 | 文件搜索、导航界面 | 快速定位、用户体验 | 全文索引、面包屑导航、视图切换 |
| 存储管理模块 | 配额管理、清理策略 | 资源控制、系统维护 | 存储统计、自动清理、监控告警 |

### 5.3 详细模块拆分

1. **空间管理模块（Space Management）**
   - **职责**：空间创建/删除/迁移/配额管理、空间元数据维护
   - **User Stories**：US001
   - **交付物**：
     - API：`POST/DELETE /api/v1/spaces`, `PUT /api/v1/spaces/{id}/quota`
     - Service：SpaceService, QuotaService
     - DB Tables：spaces, space_quotas
     - Frontend：空间管理页面、配额设置组件

2. **文件操作模块（File Operations）**
   - **职责**：文件上传/下载/重命名/移动/批量操作/回收站
   - **User Stories**：US002
   - **交付物**：
     - API：`POST/GET/PUT/DELETE /api/v1/my-space/files`
     - Service：FileService, RecycleBinService
     - DB Tables：files, file_operations_log, recycle_bin
     - Frontend：文件管理界面、拖拽上传组件、批量操作工具

3. **版本控制模块（Version Control）**
   - **职责**：版本记录、比较、回滚、白名单策略管理
   - **User Stories**：US003
   - **交付物**：
     - API：`GET /api/v1/files/{id}/versions`, `POST /api/v1/files/{id}/rollback`
     - Service：VersionService, GitService
     - DB Tables：file_versions, version_diffs
     - Frontend：版本历史页面、版本对比组件

4. **权限管理模块（Permission Management）**
   - **职责**：空间/文件夹/文件的细粒度权限、角色权限继承
   - **User Stories**：US004
   - **交付物**：
     - API：`GET/PUT /api/v1/spaces/{id}/permissions`
     - Service：PermissionService, RoleService
     - DB Tables：space_permissions, file_permissions, permission_inheritance
     - Frontend：权限设置页面、权限矩阵组件

5. **搜索导航模块（Search & Navigation）**
   - **职责**：基于Git的文件名搜索、筛选、面包屑、视图切换
   - **User Stories**：US005
   - **交付物**：
     - API：`GET /api/v1/my-space/search`, `GET /api/v1/my-space/files?filter=*`
     - Service：SearchService, GitSearchService
     - DB Tables：search_logs
     - Frontend：搜索组件、导航组件、视图切换组件

6. **存储管理模块（Storage Management）**
   - **职责**：存储配额、文件黑名单、自动清理、存储统计
   - **User Stories**：支撑所有 US
   - **交付物**：
     - API：`GET /api/v1/storage/stats`, `POST /api/v1/storage/cleanup`
     - Service：StorageService, CleanupService
     - DB Tables：storage_stats, cleanup_tasks
     - Frontend：存储统计仪表板、清理任务管理

### 6.4 API 设计规范

- **响应格式**：统一使用 `{code, message, data}` 结构
- **分页参数**：`page`, `page_size`, `total`, `total_pages`
- **筛选参数**：支持 `filter`, `sort`, `order` 等通用参数
- **错误处理**：使用标准 HTTP 状态码 + 业务错误码
- **权限验证**：所有 API 都需要通过权限中间件验证

## 7 Data（数据模型与存储设计）

### 7.1 数据架构设计

```
数据层架构
├── 关系型数据（MySQL）
│   ├── 空间元数据
│   ├── 权限关系
│   ├── 操作日志
│   └── 用户关系
├── 文件存储（Git Repository）
│   ├── 项目空间文件
│   ├── 个人空间文件
│   ├── 版本历史
│   └── Git内置搜索索引
└── 缓存层（Redis）
    ├── 权限缓存
    ├── 搜索结果缓存
    └── 会话缓存
```

### 7.2 核心数据表设计

1. **spaces（空间表）**
```sql
CREATE TABLE spaces (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    uuid VARCHAR(36) UNIQUE NOT NULL,
    name VARCHAR(255) NOT NULL,
    type ENUM('PROJECT', 'PERSONAL') NOT NULL,
    description TEXT,
    owner_id BIGINT NOT NULL,
    project_id BIGINT,
    storage_path VARCHAR(500) NOT NULL,
    quota_limit BIGINT DEFAULT 5368709120, -- 5GB
    status ENUM('ACTIVE', 'ARCHIVED', 'DELETED') DEFAULT 'ACTIVE',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_owner_id (owner_id),
    INDEX idx_project_id (project_id),
    INDEX idx_type_status (type, status)
);
```

2. **files（文件元数据表）**
```sql
CREATE TABLE files (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    space_id BIGINT NOT NULL,
    file_path VARCHAR(1000) NOT NULL,
    file_name VARCHAR(255) NOT NULL,
    file_size BIGINT NOT NULL,
    file_type VARCHAR(100),
    mime_type VARCHAR(100),
    file_hash VARCHAR(64),
    is_directory BOOLEAN DEFAULT FALSE,
    parent_path VARCHAR(1000),
    version_tracked BOOLEAN DEFAULT FALSE,
    current_version VARCHAR(40),
```

## 9 附录

### 9.1 术语定义

| 术语 | 定义 |
|------|------|
| **服务（Service）** | 独立部署的技术组件，提供特定的技术能力，如认证服务、权限服务、审计服务等。服务是技术架构层面的概念，通常以微服务或模块的形式存在。 |
| **功能特性（Feature）** | 面向用户的业务功能集合，如用户管理Feature、项目管理Feature等。Feature是产品层面的概念，通常包含多个用户故事和业务场景。 |
| **基础设施（Infrastructure）** | 底层的技术基础设施，如数据库、缓存、文件系统等，为上层服务和Feature提供技术支撑。 |
| 项目空间 | 基于项目的共享文件空间，项目成员可访问 |
| 个人空间 | 用户私有的文件空间，仅用户本人可访问 |
| Git仓库 | 用于版本控制的Git存储库 |
| 软删除 | 标记删除但不物理删除，支持恢复的删除方式 |

### 9.2 依赖关系说明

#### 文件系统依赖说明
- **Git仓库存储**：Git仓库需要文件系统作为物理存储载体，所有的文件版本、元数据都存储在文件系统中
- **工作区文件**：用户上传的文件首先存储在文件系统中，然后通过Git进行版本管理
- **临时文件处理**：文件上传、下载过程中的临时文件需要文件系统支持

#### 缓存服务依赖说明
- **权限信息缓存**：为提高权限验证性能，将用户权限信息缓存在Redis中
- **搜索结果缓存**：Git搜索结果的临时缓存，避免重复的Git操作
- **会话状态缓存**：用户会话状态和临时数据的缓存存储
- **元数据缓存**：频繁访问的文件元数据缓存，减少数据库查询

#### Git搜索机制说明
- **文件名搜索**：使用Git的文件树遍历和模式匹配实现文件名搜索
- **内容搜索**：使用`git grep`命令实现文件内容的全文搜索
- **版本搜索**：使用Git的提交历史和标签进行版本相关搜索
- **性能优化**：通过缓存搜索结果和建立文件索引提高搜索性能
