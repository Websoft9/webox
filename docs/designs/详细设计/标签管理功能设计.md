## 1. 引言

### 目的

为 Websoft9 平台提供统一的标签管理功能，支持应用、服务器、工作流等各类资源的标签化管理和分类检索。

### 范围

- 功能边界：标签的 CRUD 操作、资源关联、权限控制、批量操作
- 非目标：标签的可视化分析、智能推荐、层级结构

### 背景

随着平台资源数量增长，需要通过标签系统实现资源的灵活分类、快速检索和批量操作，提升运维效率和用户体验。

## 2. 功能概述

### 功能定位

提供平台级的标签管理服务，支持管理员创建的全局标签和用户自定义标签的统一管理。标签管理采用**隐式管理**模式，普通用户通过为资源打标签的过程中自然地创建和使用标签。

### 核心特性

- **双级标签体系**：全局标签（管理员创建，所有用户可见可用）+ 个人标签（用户创建，仅创建者可见可用）
- **隐式标签管理**：普通用户无需专门的标签管理界面，通过资源打标签过程自动创建标签
- **资源关联**：支持与任意资源类型的多对多关联
- **权限分层**：管理员维护全局标签，普通用户通过使用过程管理个人标签
- **标签晋升**：管理员可将个人标签提升为全局标签
- **按名创建**：业务模块中可通过标签名称自动创建并关联
- **自动清理**：系统自动清理未关联的个人标签，保持数据清洁

### 目标用户/使用场景

- **管理员**：维护全局标签，通过专门的管理界面管理标签规范
- **普通用户**：在为应用、服务器等资源打标签时自动创建和使用个人标签
- **业务模块**：调用标签 API 实现资源分类和检索

## 3. 依赖关系

### 依赖 Feature

- **用户管理**（强依赖）：用户认证、用户信息查询
- **权限管理**（强依赖）：RBAC 权限校验

### 依赖服务

- **认证服务**：JWT 令牌验证，获取当前用户信息
- **权限服务**：标签相关权限校验（tag:read, tag:create, tag:manage）
- **审计服务**：标签操作审计日志记录

### 基础设施依赖

- **MySQL**：标签元数据和关联关系存储
- **Redis**：标签查询缓存（由底层数据模块提供）

## 4. 业务目标与用户故事

### 业务目标

1. 提升资源管理效率，实现快速分类和检索
2. 建立统一的资源标识体系，支持跨模块标签复用
3. 降低标签维护成本，通过全局/个人标签分层管理

### 用户故事

| 角色 | 用户故事 | 验收条件 |
|------|----------|----------|
| 管理员 | 作为管理员，我希望通过专门的标签管理界面创建和维护全局标签 | 有专门的管理界面，能创建、编辑、删除全局标签 |
| 管理员 | 作为管理员，我希望将有价值的个人标签提升为全局标签，以便推广最佳实践 | 能在管理界面中看到所有个人标签使用情况，一键提升为全局标签 |
| 普通用户 | 作为用户，我希望在为应用打标签时，能够输入新标签名称并自动创建 | 在应用编辑界面的标签输入框中，输入新标签名称能自动创建个人标签 |
| 普通用户 | 作为用户，我希望在标签选择器中看到相关的标签建议，以便快速选择 | 标签选择器显示全局标签和个人标签，支持搜索和自动补全 |
| 普通用户 | 作为用户，我希望删除不需要的标签关联，系统能自动清理未使用的个人标签 | 取消标签关联后，如果个人标签没有其他关联，系统自动清理 |
| 业务模块 | 作为应用管理模块，我希望通过标签名称快速关联标签，以便简化用户操作 | 支持按名称创建并关联标签，自动创建不存在的个人标签 |

## 6. API 与契约

### 总则
- **统一前缀**：`/api/v1/tags`
- **认证**：所有接口需要 JWT 认证
- **响应格式**：`{code: int, message: string, data: any}`
- **分页规则**：`page`、`pageSize`、`total`
- **业务域架构**：按功能子域组织 API，实现业务内聚

### API 路径总览

```go
// 1. 标签基础管理域
GET    /api/v1/tags                           # 获取可见标签列表（用于选择器）
POST   /api/v1/tags                           # 创建标签（智能权限控制）
GET    /api/v1/tags/{id}                      # 获取单个标签详情
GET    /api/v1/tags/by-slug/{slug}            # 通过 slug 获取标签详情
PUT    /api/v1/tags/{id}                      # 更新标签（权限控制）
DELETE /api/v1/tags/{id}                      # 删除标签（权限控制）

// 2. 管理员功能子域
GET    /api/v1/tags/admin                     # 管理员查看所有标签（分页）
POST   /api/v1/tags/admin                     # 管理员创建全局标签
PUT    /api/v1/tags/admin/{id}                # 管理员更新任意标签
DELETE /api/v1/tags/admin/{id}                # 管理员删除任意标签
POST   /api/v1/tags/admin/{id}/promote        # 提升个人标签为全局标签
POST   /api/v1/tags/admin/cleanup             # 清理未使用的个人标签

// 3. 资源关联子域
GET    /api/v1/tags/taggings                  # 获取资源标签
POST   /api/v1/tags/taggings                  # 关联标签到资源（支持自动创建）
PUT    /api/v1/tags/taggings                  # 替换资源的所有标签
DELETE /api/v1/tags/taggings                  # 移除资源标签关联
POST   /api/v1/tags/taggings/batch            # 批量资源标签操作
GET    /api/v1/tags/taggings/search           # 按标签搜索资源
```

### 标签基础管理 API

#### 6.1 获取可见标签列表（用于标签选择器）

**描述**：获取当前用户可见的标签列表，主要用于前端标签选择器组件

**方法/路径**：`GET /api/v1/tags`

**请求参数**：
- Query参数：
  - `search` (string, 可选): 按名称搜索，支持模糊匹配
  - `limit` (int, 可选): 返回数量限制，默认50，最大100
  - `excludeIds` (string, 可选): 排除的标签ID列表，逗号分隔

**响应示例**：
```json
{
  "code": 200,
  "message": "success",
  "data": [
    {
      "id": 1,
      "name": "production",
      "slug": "production",
      "type": "environment",
      "color": "#ff0000",
      "scope": "global",
      "readOnly": true
    },
    {
      "id": 2,
      "name": "my-test",
      "slug": "my-test",
      "type": "custom",
      "color": "#0066cc",
      "scope": "personal",
      "readOnly": false
    }
  ]
}
```

**权限需求**：`tag:read`

#### 6.2 创建标签（智能权限控制）

**描述**：创建标签，根据用户权限自动判断创建全局标签或个人标签

**方法/路径**：`POST /api/v1/tags`

**请求参数**：
- Body参数：
```json
{
  "name": "新标签",
  "type": "custom",
  "color": "#0066cc",
  "description": "标签描述"
}
```

**业务逻辑**：
- 如果用户有 `tag:manage` 权限 → 创建全局标签
- 否则 → 创建个人标签

**响应示例**：
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "id": 15,
    "name": "新标签",
    "slug": "new-tag",
    "type": "custom",
    "scope": "personal",
    "ownerUserId": 123,
    "readOnly": false
  }
}
```

**权限需求**：`tag:create`

### DTO 示例

#### TagCreateRequest (管理员和普通用户通用)
```go
type TagCreateRequest struct {
    Name        string `json:"name" binding:"required,max=128" example:"production"`
```

### 并发与一致性控制

- **标签创建**：依赖数据库唯一约束，捕获 duplicate key 错误并重试查询
- **批量关联**：在单个事务中完成，确保原子性
- **标签提升**：使用行级锁防止并发提升冲突
- **Slug 生成**：采用确定性算法，相同名称生成相同 slug，冲突时添加数字后缀

### Slug 生成规则

#### 生成算法
```go
func GenerateSlug(name string, scope string, ownerUserID uint64) string {
    // 1. 基础处理
    slug := strings.TrimSpace(name)
    slug = strings.ToLower(slug)
    
    // 2. 中文转拼音处理
    slug = convertChineseToPinyin(slug)
    
    // 3. 特殊字符处理
    slug = regexp.MustCompile(`[^a-z0-9\-_]`).ReplaceAllString(slug, "-")
    slug = regexp.MustCompile(`-+`).ReplaceAllString(slug, "-")
    slug = strings.Trim(slug, "-")
    
    // 4. 长度限制
    if len(slug) > 100 {
        slug = slug[:100]
    }
    
    // 5. 冲突检测和处理
    return ensureUniqueSlug(slug, scope, ownerUserID)
}

func ensureUniqueSlug(baseSlug string, scope string, ownerUserID uint64) string {
    slug := baseSlug
    counter := 1
    
    for isSlugExists(slug, scope, ownerUserID) {
        slug = fmt.Sprintf("%s-%d", baseSlug, counter)
        counter++
    }
    
    return slug
}
```
