## 1. 引言

### 1.1 目的

本文档旨在详细描述 Websoft9 平台中**资源组（Resource Group）**功能的详细设计方案，包括 API 接口定义、数据模型、业务逻辑，为开发团队提供清晰的实现指南，为测试团队提供验收标准。

### 1.2 范围

本文档涵盖资源组的基础管理功能：
- 资源组的创建、查询、更新和删除操作
- 数据模型与存储设计
- API 接口定义与业务规则

### 1.3 背景

在 Websoft9 云应用管理平台中，用户需要管理大量跨云、跨地域的异构资源。资源组作为平台中资源的逻辑集合单元，提供按业务场景、部门、环境等维度组织资源的能力。

**平台定位：**
- **项目（Project）**：顶层资源容器，提供项目级隔离
- **资源组（Resource Group）**：项目内的资源集合单元，提供资源分类管理
- **资源（Resource）**：具体的资源实例（主机、容器实例、数据库、密钥等）

## 2. 功能概述

### 2.1 功能定位

资源组在 Websoft9 平台中作为资源逻辑分组的基本单元，提供：
- **资源分类**：按业务维度组织资源
- **权限隔离**：基于资源组实现访问控制
- **统一管理**：提供清晰的资源视图

### 2.2 核心特性

- **完整的生命周期管理**：支持创建、查询、更新、删除操作
- **细粒度权限控制**：基于角色的访问控制（Owner、Maintainer、Viewer）
- **审计日志**：记录所有操作历史

### 2.3 目标用户/使用场景

**目标用户：**
- **平台管理员**：管理所有项目的资源组
- **项目管理员**：管理项目内的资源组
- **开发团队**：使用资源组组织开发资源
- **运维团队**：使用资源组管理生产资源

**典型使用场景：**
1. **环境隔离**：创建"开发"、"测试"、"生产"资源组
2. **业务线隔离**：按业务线创建资源组
3. **团队协作**：为团队创建共享资源组

### 2.4 功能详情

**资源组管理功能：**
- 创建资源组：定义名称、编码、描述等信息
- 查询资源组列表：支持分页、筛选、搜索
- 查询资源组详情：展示基础信息
- 更新资源组：修改名称、描述等信息
- 删除资源组：软删除资源组

**业务规则：**
- 资源组名称在项目内唯一，长度 3-64 字符
- 资源组编码在项目内唯一，仅支持字母、数字、下划线

## 6. API 与契约

### 6.1 总则

**API 设计原则：**
1. **RESTful 风格**：遵循 REST 架构风格
2. **统一响应格式**：所有 API 返回统一的 JSON 格式
3. **认证授权**：所有 API 需要 JWT 认证
4. **错误处理**：返回明确的错误码和国际化错误消息

**统一响应格式：**

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

**HTTP 状态码规范：**

| 状态码 | 说明 | 使用场景 |
|--------|------|---------|
| 200 | 成功 | 请求成功 |
| 201 | 已创建 | 资源创建成功 |
| 400 | 请求错误 | 参数验证失败 |
| 401 | 未授权 | 认证失败 |
| 403 | 禁止访问 | 权限不足 |
| 404 | 未找到 | 资源不存在 |
| 409 | 冲突 | 资源已存在 |
| 500 | 服务器错误 | 服务器内部错误 |

### 6.2 API 接口汇总

| 接口名称 | HTTP 方法 | 路径 | 描述 | 权限要求 |
|---------|----------|------|------|---------|
| 创建资源组 | POST | `/api/v1/resource-groups` | 创建新资源组 | 项目管理员 |
| 查询资源组列表 | GET | `/api/v1/resource-groups` | 分页查询资源组 | 项目成员 |
| 查询资源组详情 | GET | `/api/v1/resource-groups/{id}` | 获取资源组详细信息 | 资源组成员 |
| 更新资源组 | PUT | `/api/v1/resource-groups/{id}` | 更新资源组信息 | 资源组 Owner |
| 删除资源组 | DELETE | `/api/v1/resource-groups/{id}` | 删除资源组 | 资源组 Owner |

### 6.3 核心 API 详细说明

#### 6.3.1 创建资源组

**接口描述：** 创建新的资源组，创建者自动成为资源组 Owner。

**请求信息：**
```
POST /api/v1/resource-groups
Content-Type: application/json
Authorization: Bearer {token}
```

**请求体字段说明：**

| 字段名 | 类型 | 必填 | 长度限制 | 描述 |
|--------|------|------|---------|------|
| name | string | 是 | 3-64 | 资源组名称，项目内唯一 |
| code | string | 是 | 3-32 | 资源组编码，项目内唯一，仅支持字母、数字、下划线 |
| description | string | 否 | 0-500 | 资源组描述 |
| sort_order | integer | 否 | - | 排序顺序 |

**请求示例：**
```json
{
  "name": "生产环境资源组",
  "code": "production",
  "description": "生产环境所有资源",
  "sort_order": 1
}
```

**响应示例（成功）：**
```json
{
  "code": 200,
  "message": "创建成功"
}
```

**业务规则：**
1. 资源组名称在项目内唯一
2. 资源组编码在项目内唯一，仅支持字母、数字、下划线
3. 创建者自动成为资源组 Owner

**错误码：**
- `400`：参数验证失败
- `401`：未认证
- `403`：无权限
- `409`：名称或编码已存在
- `500`：服务器内部错误

## 9. 数据模型与存储设计

### 9.1 数据架构概述

资源组模块采用关系型数据库（MySQL/PostgreSQL）存储核心数据。

### 9.2 关键表设计

**资源组表（resource_groups）**

| 字段名      | 类型            | 约束               | 默认值                                        | 注释                 |
| ----------- | --------------- | ------------------ | --------------------------------------------- | -------------------- |
| id          | BIGINT UNSIGNED | PK, AUTO_INCREMENT | -                                             | 资源组ID             |
| project_id  | BIGINT UNSIGNED | NOT NULL, FK       | -                                             | 项目ID               |
| name        | VARCHAR(64)     | NOT NULL           | -                                             | 资源组名称           |
| code        | VARCHAR(32)     | NOT NULL, UNIQUE   | -                                             | 资源组编码           |
| description | TEXT            | -                  | NULL                                          | 资源组描述           |
| owner_id    | BIGINT UNSIGNED | NOT NULL, FK       | -                                             | 所有者ID             |
| sort_order  | INT             | -                  | 0                                             | 排序                 |
| status      | TINYINT(1)      | -                  | 1                                             | 状态：0-禁用，1-启用 |
| created_at  | DATETIME        | NOT NULL           | CURRENT_TIMESTAMP                             | 创建时间             |
| updated_at  | DATETIME        | NOT NULL           | CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间             |

**索引设计：**
- PRIMARY KEY (id)
- UNIQUE INDEX idx_project_code (project_id, code)
- INDEX idx_project_name (project_id, name)
- INDEX idx_owner_id (owner_id)

## 10. 实现要点与关键数据流

### 10.1 资源组创建流程

1. 接收创建请求，验证参数
2. 校验用户权限（项目管理员）
3. 检查名称和编码唯一性
4. 创建资源组记录
5. 创建者自动成为 Owner
6. 返回成功响应

### 10.2 资源组删除流程

1. 接收删除请求
2. 校验用户权限（资源组 Owner）
3. 查询资源组是否存在
4. 执行软删除操作
5. 返回成功响应
