## 2 功能概述

### 2.1 功能定位

`空间` （英文名称为 Space 或 Repository）是基于 Git 的本地文件管理系统。它利用 Git 的版本控制特性，将文件存储和版本管理结合，实现高效的文件增删改查（CRUD）和历史追踪。空间主要存储工作负载所需的部署模板、配置文件和脚本文件，实现集中式的 GitOps 管理能力。

### 2.2 核心特性

- **两种空间应用场景**：支持项目空间（团队共享）和个人空间（私人使用）
- **文件管理**：支持文件增、删、改、查、编辑、预览、移动等操作，文件夹的创建与移动
- **版本控制**：基于Git的文件版本管理，支持特定文件类型的版本追踪、回滚以及查询变更日志
- **权限管理**：支持细粒度的文件和文件夹权限控制
- **安全保护**：文件回收站机制，防止误删除
- **高效搜索**：支持文件名和内容的全文搜索
- **存储配额**：灵活的存储空间配额管理

### 2.3 技术架构

#### 2.3.1 整体架构分层

```
┌─────────────────────────────────────────────────────────────┐
│                    用户层 (浏览器/客户端)                     │
└─────────────────────┬───────────────────────────────────────┘
                      │ HTTP/HTTPS
┌─────────────────────▼───────────────────────────────────────┐
│                  网关层 (Nginx)                            │
│              代理转发 | SSL | 限流                          │
└─────────────────────┬───────────────────────────────────────┘
                      │ REST API
┌─────────────────────▼───────────────────────────────────────┐
│                  API层 (Gin框架)                           │
│         路由 | 鉴权 | 校验 | 响应格式 | 审计拦截             │
└─────────────────────┬───────────────────────────────────────┘
                      │ 服务调用
┌─────────────────────▼───────────────────────────────────────┐
│                   服务层 (业务逻辑)                         │
│  空间管理 | 文件操作 | 版本控制 | 权限管理 | 搜索 | 存储      │

#### 2.3.2 核心组件与职责

**网关层 (Nginx)**
- 统一入口与反向代理
- SSL/TLS 终结
- 基础安全头与限流

**API层 (Gin + 中间件)**
- RESTful 路由管理
- JWT 认证与权限校验
- 请求参数验证
- 统一响应格式化
- 审计中间件自动记录

**服务层 (核心业务组件)**
- **空间管理**: SpaceService, GitRepositoryService, MigrationService
- **文件操作**: FileService, UploadService, RecycleBinService, PreviewService  
- **版本控制**: VersionService, DiffService, RollbackService
- **权限管理**: PermissionService, RoleService
- **搜索导航**: SearchService (基于git grep), NavigationService
- **存储管理**: QuotaService, CleanupService, StorageService
- **配置管理**: GitConfigService

**存储层 (混合存储策略)**
- **Git仓库**: 文件内容 + 版本历史 + 分支管理 (main/recycle)
- **MySQL**: 元数据索引 + 权限关系 + 回收站索引
- **文件系统**: Git仓库物理存储载体

#### 2.3.3 关键数据流

**文件上传流程:**
```
用户请求 → 鉴权校验 → 配额检查 → 文件保存 → Git提交(聚合) → 元数据更新 → 响应返回
```

**文件删除流程:**
```
删除请求 → 权限验证 → Git移动到recycle分支 → 更新recycle_index → 返回确认
```

**文件恢复流程:**
```
恢复请求 → 权限验证 → 从recycle分支cherry-pick → 更新索引状态 → 返回结果
```

**版本回滚流程:**
```
回滚请求 → 权限验证 → Git checkout指定版本 → 创建新提交 → 审计记录 → 返回确认
```

#### 2.3.4 核心设计原则

**存储策略**
- Git作为唯一文件版本真实来源，避免重复实现版本控制逻辑
- MySQL仅存储必要的元数据与索引，加速查询性能
- 回收站通过独立recycle分支实现，配合数据库索引优化列表查询

**版本控制策略**
- 自动提交聚合机制(默认20秒)，减少碎片化提交
- 仅对白名单文本文件类型提供差异比较功能
- 保持完整的Git提交历史，确保可追溯性

**权限控制策略**
- 基于RBAC模型的多层权限体系
- 权限验证集中在服务层入口
- 支持权限继承与显式覆盖机制

**简化原则**
- 当前版本不引入缓存、消息队列、高可用等复杂组件
- 单实例部署，降低实现与运维复杂度
- 保留清晰的扩展接入点，支持后续演进

#### 2.3.5 技术栈选择

- **后端框架**: Go + Gin + GORM
- **数据库**: MySQL 8.0+ (生产) / SQLite (开发)
- **版本控制**: Git 2.0+ 命令行工具
- **认证**: JWT Token
- **日志**: Zap 结构化日志
- **文档**: Swagger/OpenAPI
- **部署**: Docker + Docker Compose

### 3.6 风险评估与应对

**高风险依赖：**
- **认证服务不可用**：项目空间完全无法使用
  - 应对：实现认证服务的高可用部署，设计降级策略
- **权限服务故障**：可能导致权限控制失效
  - 应对：实现权限缓存机制，设置默认安全策略

**中风险依赖：**
- **用户管理变更**：可能影响用户信息获取
  - 应对：定义稳定的数据接口，使用数据适配层
- **项目管理调整**：可能影响项目关联逻辑
  - 应对：通过事件驱动架构解耦，避免直接依赖

**低风险依赖：**
- **通知服务异常**：仅影响通知功能，不影响核心业务
  - 应对：异步处理，允许通知失败

## 4 Business（业务目标与用户故事）

### 4.1 业务目标概述

- 统一项目内外文件管理，提供版本控制与权限管理
- 减少重复配置与资料丢失风险
- 支持团队协作的文件共享与版本追踪

### 4.2 核心用户故事拆分

1. **US001 - 空间管理**
   - 作为项目管理员，我希望创建/删除项目空间，以便管理项目文件归属
   - 作为普通用户，我希望拥有个人私有空间保存私密文件
   - 作为管理员，我希望配置空间存储配额，以便控制资源使用

2. **US002 - 文件操作**
   - 作为项目成员，我希望上传/下载/移动/编辑/预览文件，保证协作效率
   - 作为用户，我希望批量操作文件，提高工作效率
   - 作为用户，我希望通过拖拽方式上传文件，提升使用体验

3. **US003 - 版本控制**
   - 作为用户，我希望查看文件版本历史，以便追溯变更
   - 作为用户，我希望回滚到历史版本，确保数据安全
   - 作为审计员，我希望查看文件操作日志，便于审计追踪

4. **US004 - 权限管理**
   - 作为项目管理员，我希望设置文件和文件夹权限，控制成员访问范围
   - 作为用户，我希望分享文件给特定成员，支持协作
   - 作为管理员，我希望无法查看个人空间内容，保护隐私

5. **US005 - 搜索与导航**
   - 作为用户，我希望快速搜索和筛选文件，提高查找效率
   - 作为用户，我希望使用面包屑导航，方便目录跳转
   - 作为用户，我希望切换不同视图方式，适应不同使用场景

### 5.3 详细模块拆分

#### 5.3.1 空间管理模块（Space Management）
**核心职责**：空间元数据管理、生命周期管理、配额策略、多租户隔离

**详细设计**：
- **元数据设置**：
  - 基本信息：空间ID（UUID，不可修改）、空间名称、描述信息、
  - 时间信息：创建时间、最后修改时间
  - 文件配额：
    - 最大文件数量：单个文件夹下直接的最大文件数量 默认配额 1000 个
    - 单个文件大小限制：默认配额 500M
    - 文件类型黑名单：支持以后缀名作为文件类型黑名单配置
    - 可预览文件大小限制：阈值 1M，即超过 1M 的文件不提供在线预览
    - 可编辑文件大小限制：阈值 1M，即超过 1M 的文件不提供在线编辑
    - 文件在回收站存放时间：默认 30 天
  - 版本控制策略：
    - 文件版本历史保留数量（默认50个版本）
    - 自动提交间隔设置（默认 20s）
    - 版本控制白名单配置: 基于版本控制模块的技术实现，使用.gitignore规范限制仅对文本文件、特定文件类型进行版本控制

      ```
- **空间类型策略**：
  - 项目空间：基于项目ID创建，支持团队协作，继承项目权限
  - 个人空间：基于用户ID创建，私有存储
- **配额管理策略**：
  - 硬配额：超限阻止上传，软配额：超限告警
  - 配额继承：项目空间继承项目配额，个人空间使用用户配额
- **空间初始化**：
  - 仓库初始化：自动创建.gitignore、README.md，配置Git基础设置
  - Git配置管理：支持仓库级用户信息配置，Owner信息从User功能获取
- **空间迁移**：
  - 支持将空间迁移为其他空间的子文件夹
  - 迁移过程保留文件版本历史
  - 迁移后自动更新权限设置
  - 回收站文件不需要迁移

- **空间导出**：
  - 压缩下载：将空间压缩后，提供下载地址
  - 远程仓库：支持手工触发同步到远程仓库

**交付物**：
- Service：SpaceService, QuotaService, GitRepositoryService, GitConfigService, MigrationService
- Git Operations：仓库初始化、仓库迁移、配额检查、Git配置管理
- Frontend：空间创建向导、配额监控仪表板、空间设置页面、Git配置管理页面
- API设计：详见6.2核心API设计

#### 5.3.2 文件操作模块（File Operations）
**核心职责**：文件CRUD操作、批量处理、回收站机制

**详细设计**：
- **上传策略**：
  - 分片上传：大文件（>100MB）自动分片
  - 去重机制：基于SHA256哈希值去重
  - 格式验证：支持黑名单策略

- **基本操作**：
  - 支持新建、删除、复制、移动或重命名文件夹
  - 支持新建、删除、复制、移动或重命名文件

- **批量操作**：
  - 支持拖拽多文件上传、批量下载、打包下载、批量删除
  - 操作队列：异步处理批量操作，支持进度监控

- **回收站文件操作**：
  - 回收机制：删除的文件和文件夹通过Git操作移动到recycle分支，实现基于Git的软删除
  - 恢复功能：从recycle分支恢复文件到main分支的原位置或指定位置
  - 彻底删除：从recycle分支中永久删除文件，释放Git仓库存储空间
  - 批量操作：支持批量恢复和批量彻底删除，通过Git批量操作实现

- **文件预览与编辑**：
  - 支持图片、PDF、文本文件在线预览
  - 支持文本文件在线编辑

  >  后端仅提供文件的 URL 


**交付物**：
- Service：FileService, UploadService, RecycleBinService, PreviewService
- Git Operations：文件操作、分支管理、回收站管理
- Frontend：文件管理器、拖拽上传组件、批量操作工具、回收站管理界面、预览组件
- API设计：详见6.2核心API设计


#### 5.3.3 版本控制模块（Version Control）
**核心职责**：文件版本管理、差异对比、安全回滚

**详细设计**：
- **版本追踪范围**：
  - Git天然对所有文件进行版本控制，无需额外配置
  - 白名单策略：仅对特定文件类型（.md、.json、.yaml等）提供版本比较和差异查看功能
  - 通过.gitignore配置排除不需要差异分析的大文件或二进制文件

- **版本管理**：
  - 自动提交：文件修改后自动创建Git提交，记录变更历史
  - 提交策略：支持配置自动提交间隔（默认20秒）来聚合频繁修改
  - 版本标识：使用Git原生的commit hash作为版本标识

- **版本比较**：
  - 差异算法：使用Git diff对文本文件进行行级差异对比
  - 可视化界面：提供并排对比视图，支持语法高亮
  - 元数据对比：文件大小、修改时间、作者信息对比

- **版本回滚**：
  - 安全检查：回滚前进行权限验证和冲突检测
  - 回滚策略：使用Git checkout恢复文件到指定版本，创建新提交记录
  - 保持可追溯性：所有回滚操作都会产生新的Git提交

- **变更日志**：
  - Git提交历史：直接使用Git log获取文件变更历史
  - 提交信息：包含操作类型、用户信息、时间戳
  - 审计集成：重要操作同步到审计服务

**交付物**：
- Service：VersionService, GitService, DiffService, RollbackService
- Git Operations：提交管理、差异计算、版本恢复
- Frontend：版本历史页面、差异对比器、回滚确认对话框
- API设计：详见6.2核心API设计


#### 5.3.4 权限管理模块（Permission Management）
**核心职责**：多层次权限控制、权限继承、访问审计

**详细设计**：

- **平台权限**：
  - 平台管理员默认拥有所有空间的 Owner 权限

- **项目空间权限**：
  - 项目拥有者：完全控制权限，包括成员管理、权限设置、空间配置
  - 项目成员：默认读写权限，可被项目拥有者限制特定操作
  - 权限粒度：支持按用户或角色设置文件/文件夹级别的权限
  - 权限继承：子文件夹继承父文件夹权限，可显式覆盖

- **个人空间权限**：
  - 空间拥有者：拥有完全控制权限，独享空间内容
  - 平台管理员：仅可进行空间管理操作（配额、迁移等），无法查看空间内容
  - 隐私保护：确保个人空间内容的绝对私密性

- **权限类型定义**：
  - 读取权限（READ）：查看文件列表、下载文件、预览文件内容
  - 写入权限（WRITE）：上传文件、编辑文件、创建文件夹、文件移动
  - 删除权限（DELETE）：删除文件、删除文件夹、回收站操作
  - 管理权限（MANAGE）：设置权限、空间配置、版本管理、成员管理

- **权限验证机制**：
  - 基于RBAC模型的权限验证，支持用户和角色两种授权方式
  - 权限审计：记录所有权限变更和访问操作，支持合规追踪

- **权限控制策略**：
  - 最小权限原则：用户仅获得完成任务所需的最小权限
  - 权限分离：读写权限独立控制，支持只读共享场景

**交付物**：
- Service：PermissionService, RoleService, PermissionCacheService
- Git Operations：权限检查、访问控制
- Frontend：权限矩阵管理、角色分配器、权限审计查看器
- API设计：详见6.2核心API设计


#### 5.3.5 搜索导航模块（Search & Navigation）
**核心职责**：智能搜索、高级筛选、目录导航、多视图展示

**详细设计**：
- **搜索功能**：
  - 文件名搜索：支持关键词模糊查询，包含拼音搜索和首字母搜索
  - 全文搜索：基于Git grep对文本文件内容进行搜索，支持正则表达式
  - 搜索范围：支持当前目录、子目录、整个空间的搜索范围设置
  - 结果排序：支持相关度、时间、大小、名称等多种排序方式

- **高级筛选**：
  - 文件类型筛选：按文件扩展名进行分类筛选
  - 时间筛选：按创建时间、修改时间进行时间段筛选（今天、本周、本月、自定义）
  - 大小筛选：按文件大小范围筛选（小于1MB、1-10MB、大于10MB、自定义）
  - 用户筛选：按创建者、修改者进行筛选

- **目录导航**：
  - 面包屑导航：底部工具栏显示完整路径，支持点击快速跳转

- **视图切换**：
  - 列表视图：紧凑型列表，显示文件基本信息（名称、大小、修改时间）
  - 网格视图：图标网格布局，适合图片和媒体文件展示
  - 详细视图：展示完整的文件元数据（权限、版本、创建者等）

**交付物**：
- Service：SearchService, FilterService, NavigationService, ViewService
- Git Operations：Git grep搜索、文件树遍历
- Frontend：搜索组件、筛选器、面包屑导航、视图切换器
- API设计：详见6.2核心API设计

#### 5.3.6 存储管理模块（Storage Management）
**核心职责**：存储监控、配额管理、自动化清理

**详细设计**：
- **存储监控**：
  - Git仓库大小监控：通过`git count-objects -v`和`du -sh`获取仓库真实大小
  - 分支存储统计：分别监控main分支和recycle分支的存储占用
  - 配额检查：实时检查空间使用是否超出配额限制

- **配额管理策略**：
  - 个人空间默认配额：1GB
  - 项目空间默认配额：5GB  
  - 硬配额执行：当达到配额限制时阻止新文件上传
  - 软配额告警：当使用率达到80%时发送告警通知

- **自动清理策略**：
  - 回收站自动清理：定期清理recycle分支中超过保留期的文件
  - Git垃圾回收：定期执行`git gc --prune`清理悬空对象
  - 空仓库清理：清理长期未使用的空Git仓库

**交付物**：
- Service：StorageService, QuotaService, CleanupService
- Git Operations：仓库大小统计、分支清理、垃圾回收
- Frontend：存储监控仪表板、配额设置界面
- API设计：详见6.2核心API设计


#### 5.3.7 Git配置管理模块（Git Configuration Management）
**核心职责**：Git仓库配置管理、用户信息获取、配置优先级控制

**详细设计**：
- **配置获取策略**：
  - 优先级1：空间自定义配置（spaces表中的git_user_name/git_user_email）
  - 优先级2：从User功能获取用户信息
  - 优先级3：Git全局配置兜底

- **配置管理**：
  - 仓库级配置：每个空间可以独立设置Git用户信息
  - 动态配置：支持运行时更新Git配置，立即生效
  - 配置验证：验证邮箱格式、用户名有效性

- **用户信息集成**：
  - 与User功能集成：自动获取空间Owner的用户信息
  - 信息同步：支持从用户资料更新Git配置
  - 兜底策略：用户信息不可用时使用Git全局配置

- **配置应用**：
  - 新提交时应用：文件操作时使用当前配置的用户信息
  - 配置持久化：将配置写入Git仓库和数据库
  - 配置查看：提供配置来源和可用选项的完整视图

**交付物**：
- Service：GitConfigService, UserInfoService
- Git Operations：仓库配置读写、全局配置获取
- Frontend：Git配置管理页面、用户信息绑定界面
- API设计：详见6.4 Git配置管理API详细示例

### 6.5 API 设计规范

- **响应格式**：统一使用 `{code, message, data}` 结构
- **分页参数**：`page`, `page_size`, `total`, `total_pages`
- **筛选参数**：支持 `filter`, `sort`, `order` 等通用参数
- **错误处理**：使用标准 HTTP 状态码 + 业务错误码
- **权限验证**：所有 API 都需要通过权限中间件验证
- **路径规范**：统一使用 `/api/v1/spaces/{space_id}/` 前缀，支持多空间管理
- **兼容性**：保留 `/api/v1/my-space/` 快捷路径，方便用户访问个人空间

### 7.4 Git仓库配置管理

基于Websoft9项目架构，Git配置采用分层策略：

#### Docker层配置（全局基础配置）
```dockerfile
# ...existing code...
# 设置全局默认Git配置
RUN git config --global init.defaultBranch "main" && \
    git config --global core.autocrlf false && \
    git config --global core.fileMode false
# ...existing code...
```

#### 仓库层配置（空间特定配置）
```go
type GitConfig struct {
    UserName  string `json:"user_name"`
    UserEmail string `json:"user_email"`
    AutoCommitInterval int `json:"auto_commit_interval"`
    RecycleRetentionDays int `json:"recycle_retention_days"`
}

// 配置获取优先级：
// 1. 空间表中的git_user_name/git_user_email
// 2. 从User功能获取用户信息
// 3. Git全局配置兜底
func (s *GitConfigService) GetRepoConfig(ctx context.Context, spaceID int64) (*GitConfig, error) {
    space, err := s.spaceRepo.GetByID(ctx, spaceID)
    if err != nil {
        return nil, err
    }

    config := &GitConfig{
        AutoCommitInterval: space.AutoCommitInterval,
        RecycleRetentionDays: space.RecycleRetentionDays,
    }

    // 优先使用空间配置的Git用户信息
    if space.GitUserName != "" && space.GitUserEmail != "" {
        config.UserName = space.GitUserName
        config.UserEmail = space.GitUserEmail
        return config, nil
    }

    // 从User功能获取Owner信息
    if user, err := s.userService.GetUserInfo(ctx, space.OwnerID); err == nil {
        config.UserName = user.Username
        config.UserEmail = user.Email
        return config, nil
    }

    // 使用Git全局配置兜底
    globalConfig, _ := s.getGlobalGitConfig(space.GitRepoPath)
    config.UserName = globalConfig.UserName
    config.UserEmail = globalConfig.UserEmail
    
    return config, nil
}
```

## 9 附录

### 9.1 术语定义

| 术语 | 定义 |
|------|------|
| **服务（Service）** | 独立部署的技术组件，提供特定的技术能力，如认证服务、权限服务、审计服务等。服务是技术架构层面的概念，通常以微服务或模块的形式存在。 |
| **功能特性（Feature）** | 面向用户的业务功能集合，如用户管理Feature、项目管理Feature等。Feature是产品层面的概念，通常包含多个用户故事和业务场景。 |
| **基础设施（Infrastructure）** | 底层的技术基础设施，如数据库、缓存、文件系统等，为上层服务和Feature提供技术支撑。 |
| 项目空间 | 基于项目的共享文件空间，项目成员可访问 |

| 软删除 | 标记删除但不物理删除，支持恢复的删除方式 |

### 9.2 依赖关系说明

#### 文件系统依赖说明
- **Git仓库存储**：Git仓库需要文件系统作为物理存储载体，所有的文件版本、元数据都存储在文件系统中
- **工作区文件**：用户上传的文件首先存储在文件系统中，然后通过Git进行版本管理
- **临时文件处理**：文件上传、下载过程中的临时文件需要文件系统支持

#### Git搜索机制说明
- **文件名搜索**：使用Git的文件树遍历和模式匹配实现文件名搜索
- **内容搜索**：使用`git grep`命令实现文件内容的全文搜索
- **版本搜索**：使用Git的提交历史和标签进行版本相关搜索
- **性能优化**：通过Git内置索引提高搜索性能，适合小规模用户场景

#### Git配置管理说明
- **分层配置**：Docker层提供全局基础配置，空间层提供个性化配置
- **配置优先级**：空间自定义配置 > 用户信息 > Git全局配置
- **动态更新**：支持运行时更新Git配置，无需重启服务
