## 2. 背景与目标

### 2.1 业务背景

在 Websoft9 云应用管理平台中，用户需要对大量的云资源（主机、容器、数据库、存储等）进行统一管理。资源组作为资源的逻辑集合单元，帮助用户实现：

- **资源分类管理**：按业务场景、部门、环境等维度组织资源
- **权限隔离**：基于资源组实现细粒度的访问控制
- **配额管理**：限制资源组可使用的资源量，避免资源滥用
- **成本核算**：按资源组统计资源使用成本
- **批量操作**：对资源组内资源执行批量管理操作

### 2.2 功能目标

- 提供完整的资源组生命周期管理（创建、查询、更新、删除）
- 支持多种资源类型的统一管理（主机、容器、数据库、网络、存储）
- 实现基于资源组的成员管理和权限控制
- 提供配额管理和使用监控功能
- 支持资源组标签和元数据管理
- 提供完整的审计日志记录

### 2.3 约束与假设

- 资源组必须归属于某个项目，不能跨项目共享
- 单个资源只能属于一个资源组
- 资源组的配额不能超过所属项目的配额
- 删除资源组前必须先解绑所有资源
- 平台管理员和项目管理员具有所有资源组的管理权限

## 3. 术语定义

| 术语 | 英文 | 定义 |
|------|------|------|
| 资源组 | Resource Group | 用于组织和管理云资源的逻辑集合 |
| 配额 | Quota | 对资源使用量的限制，包括数量和规格 |
| 成员 | Member | 具有资源组访问权限的用户 |
| 资源绑定 | Resource Binding | 资源与资源组的关联关系 |
| 标签 | Tag | 用于标识和分类资源组的键值对 |
| 生命周期 | Lifecycle | 资源组从创建到删除的完整过程 |

### 4.2 业务流程

#### 4.2.1 资源组创建流程

```
用户发起创建 → 填写基础信息 → 设置配额 → 选择标签 
    ↓
权限校验 → 配额校验 → 创建资源组记录 
    ↓
初始化权限 → 记录审计日志 → 返回结果
```

**流程说明：**
1. 项目管理员或授权用户在项目空间发起创建资源组请求
2. 填写资源组名称、描述、所属项目等基础信息
3. 配置 CPU、内存、存储、实例数等资源配额
4. 添加自定义标签用于分类和检索
5. 系统验证用户是否有创建资源组的权限
6. 检查配额是否超过项目限额
7. 在数据库中创建资源组记录
8. 为创建者分配资源组所有者角色
9. 记录创建操作的审计日志
10. 返回创建成功的资源组信息

#### 4.2.2 资源绑定流程

```
选择资源 → 选择目标资源组 → 权限校验 
    ↓
资源状态校验 → 配额校验 → 创建绑定关系 
    ↓
更新资源标签 → 同步监控配置 → 记录审计日志 → 返回结果
```

**流程说明：**
1. 用户在资源列表中选择需要加入资源组的资源
2. 选择目标资源组
3. 验证用户是否有资源的管理权限和资源组的写权限
4. 检查资源是否处于可绑定状态（未绑定其他资源组）
5. 检查绑定后是否超出资源组配额
6. 在映射表中创建资源与资源组的关联记录
7. 为资源添加资源组标签
8. 通知监控服务更新采集配置
9. 记录绑定操作的审计日志
10. 返回绑定成功的信息

#### 4.2.3 成员管理流程

```
添加成员 → 选择用户 → 分配角色 → 权限校验 
    ↓
发送邀请 → 用户确认 → 创建成员记录 
    ↓
同步 RBAC → 记录审计日志 → 返回结果
```

**流程说明：**
1. 资源组管理员发起添加成员请求
2. 从用户列表中选择要添加的用户
3. 为用户分配角色（Owner、Maintainer、Viewer）
4. 验证操作者是否有成员管理权限
5. 向被邀请用户发送通知
6. 用户确认加入资源组
7. 在成员表中创建记录
8. 更新 RBAC 权限控制系统
9. 记录成员管理操作的审计日志
10. 返回操作成功信息

#### 4.2.4 资源组删除流程

```
发起删除 → 权限校验 → 资源检查 → 任务检查 
    ↓
冻结资源组 → 解绑所有资源 → 移除所有成员 
    ↓
备份元数据 → 软删除记录 → 记录审计日志 → 返回结果
```

**流程说明：**
1. 管理员发起删除资源组请求
2. 验证是否有删除权限
3. 检查是否有资源绑定（要求先解绑）
4. 检查是否有运行中的任务
5. 将资源组状态设置为冻结，禁止新操作
6. 解除所有资源的绑定关系
7. 移除所有成员的访问权限
8. 备份资源组的配置和历史数据
9. 标记资源组为已删除状态
10. 记录删除操作的审计日志
11. 返回删除成功信息

```
                            ↓

                            ↓
```

## 7. 数据设计

### 7.1 数据模型

#### 7.1.1 资源组表 (resource_groups)

```sql
CREATE TABLE resource_groups (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    project_id BIGINT NOT NULL,
    name VARCHAR(64) NOT NULL,
    description TEXT,
    status VARCHAR(20) NOT NULL DEFAULT 'active',
    
    -- 配额
    quota_cpu INT,
    quota_memory BIGINT,
    quota_storage BIGINT,
    quota_instances INT,
    
    -- 元数据
    tags JSON,
    metadata JSON,
    
    -- 审计
    created_by BIGINT,
    updated_by BIGINT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    deleted_at TIMESTAMP NULL,
    
    INDEX idx_project_id (project_id),
    INDEX idx_status (status),
    UNIQUE KEY uk_project_name (project_id, name, deleted_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

#### 7.1.2 资源绑定表 (resource_group_bindings)

```sql
CREATE TABLE resource_group_bindings (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    resource_group_id BIGINT NOT NULL,
    resource_id VARCHAR(128) NOT NULL,
    resource_type VARCHAR(32) NOT NULL,
    resource_name VARCHAR(128),
    status VARCHAR(20) NOT NULL DEFAULT 'active',
    
    -- 规格信息
    cpu_cores INT,
    memory_mb BIGINT,
    storage_gb BIGINT,
    
    extra_metadata JSON,
    
    created_by BIGINT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    deleted_at TIMESTAMP NULL,
    
    INDEX idx_resource_group_id (resource_group_id),
    INDEX idx_resource_id (resource_id),
    INDEX idx_resource_type (resource_type),
    UNIQUE KEY uk_binding (resource_group_id, resource_id, deleted_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

#### 7.1.3 成员表 (resource_group_members)

```sql
CREATE TABLE resource_group_members (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    resource_group_id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    role VARCHAR(32) NOT NULL,
    status VARCHAR(20) NOT NULL DEFAULT 'active',
    
    invited_by BIGINT,
    joined_at TIMESTAMP,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    deleted_at TIMESTAMP NULL,
    
    INDEX idx_resource_group_id (resource_group_id),
    INDEX idx_user_id (user_id),
    INDEX idx_role (role),
    UNIQUE KEY uk_member (resource_group_id, user_id, deleted_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

#### 7.1.4 审计日志表 (resource_group_audits)

```sql
CREATE TABLE resource_group_audits (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    resource_group_id BIGINT NOT NULL,
    action VARCHAR(64) NOT NULL,
    actor_id BIGINT NOT NULL,
    actor_type VARCHAR(32) NOT NULL,
    
    target_type VARCHAR(32),
    target_id VARCHAR(128),
    payload JSON,
    result VARCHAR(20),
    error_message TEXT,
    
    ip_address VARCHAR(45),
    user_agent TEXT,
    
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    
    INDEX idx_resource_group_id (resource_group_id),
    INDEX idx_actor_id (actor_id),
    INDEX idx_action (action),
    INDEX idx_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

#### 7.2.3 成员角色

| 角色 | 说明 | 权限 |
|------|------|------|

### 7.3 索引设计

**主要索引：**
- `idx_project_id`：按项目查询资源组
- `idx_resource_group_id`：查询资源组的资源和成员
- `idx_resource_id`：查询资源所属的资源组
- `idx_created_at`：按时间查询审计日志

**唯一索引：**
- `uk_project_name`：项目内资源组名称唯一
- `uk_binding`：资源只能绑定一个资源组
- `uk_member`：用户在资源组内唯一

## 8. 接口设计

### 8.1 RESTful API

#### 8.1.1 资源组管理

**创建资源组**
```
POST /api/v1/projects/{projectID}/resource-groups
```

请求体：
```json
{
  "name": "生产环境资源组",
  "description": "生产环境所有资源",
  "quota": {
    "cpu": 64,
    "memory": 131072,
    "storage": 2048,
    "instances": 50
  },
  "tags": {
    "env": "production",
    "team": "ops"
  }
}
```

响应：
```json
{
  "code": 200,
  "message": "创建成功",
  "data": {
    "id": 123,
    "name": "生产环境资源组",
    "project_id": 1,
    "status": "active",
    "created_at": "2024-01-20T10:00:00Z"
  }
}
```

**查询资源组列表**
```
GET /api/v1/projects/{projectID}/resource-groups
```

查询参数：
- `page`: 页码（默认1）
- `page_size`: 每页数量（默认20）
- `status`: 状态筛选
- `keyword`: 关键词搜索

**查询资源组详情**
```
GET /api/v1/resource-groups/{id}
```

**更新资源组**
```
PUT /api/v1/resource-groups/{id}
```

**删除资源组**
```
DELETE /api/v1/resource-groups/{id}
```

**冻结资源组**
```
POST /api/v1/resource-groups/{id}/freeze
```

**解冻资源组**
```
POST /api/v1/resource-groups/{id}/unfreeze
```

#### 8.1.2 资源绑定管理

**绑定资源**
```
POST /api/v1/resource-groups/{id}/resources
```

请求体：
```json
{
  "resource_id": "host-001",
  "resource_type": "host",
  "resource_name": "Web服务器1",
  "cpu_cores": 4,
  "memory_mb": 8192,
  "storage_gb": 100
}
```

**批量绑定资源**
```
POST /api/v1/resource-groups/{id}/resources/batch
```

**解绑资源**
```
DELETE /api/v1/resource-groups/{id}/resources/{resourceID}
```

**查询资源列表**
```
GET /api/v1/resource-groups/{id}/resources
```

#### 8.1.3 成员管理

**添加成员**
```
POST /api/v1/resource-groups/{id}/members
```

请求体：
```json
{
```

## 9. 业务规则与校验

### 9.1 创建规则

- 资源组名称长度：3-64 字符
- 名称在项目内唯一
- 配额不能超过项目配额
- 必须指定所属项目

### 9.2 绑定规则

- 资源只能绑定一个资源组
- 绑定后配额使用不能超限
- 资源必须处于可用状态
- 必须有资源的管理权限

### 9.3 成员管理规则

- 资源组至少保留一个 Owner
- 用户在资源组内角色唯一
- 移除 Owner 需先转让角色

### 9.4 删除规则

- 删除前必须解绑所有资源
- 删除前必须移除所有成员（Owner 除外）
- 无运行中的任务
- 支持软删除和硬删除

### 9.5 配额规则

- 配额调整不能低于当前使用量
- 配额调整不能超过项目配额
- 资源组冻结时不能调整配额
- 配额调整需记录审计日志

## 10. 权限与安全

### 10.1 权限模型

**基于 RBAC 的权限控制：**

| 角色 | 权限范围 |
|------|---------|
| 平台管理员 | 所有资源组的所有操作 |
| 项目管理员 | 项目内所有资源组的所有操作 |
| 资源组 Owner | 资源组的所有操作 |
| 资源组 Maintainer | 资源和成员管理 |
| 资源组 Viewer | 仅查看 |

### 10.2 权限矩阵

| 操作 | Owner | Maintainer | Viewer |
|------|-------|------------|--------|
| 查看资源组 | ✓ | ✓ | ✓ |
| 更新资源组 | ✓ | ✗ | ✗ |
| 删除资源组 | ✓ | ✗ | ✗ |
| 绑定资源 | ✓ | ✓ | ✗ |
| 解绑资源 | ✓ | ✓ | ✗ |
| 添加成员 | ✓ | ✓ | ✗ |
| 移除成员 | ✓ | ✓ | ✗ |
| 更新配额 | ✓ | ✗ | ✗ |
| 查看日志 | ✓ | ✓ | ✓ |

### 10.3 安全措施

- **认证**：所有 API 需 JWT 认证
- **授权**：基于 RBAC 的细粒度权限控制
- **审计**：所有操作记录审计日志
- **加密**：敏感数据传输加密
- **限流**：API 请求限流保护
- **防重放**：关键操作防重放攻击
- **输入验证**：严格的输入参数校验

## 13. 风险与应对

| 风险 | 等级 | 影响 | 应对措施 |
|------|------|------|---------|
| 配额同步延迟 | 高 | 超卖 | 消息队列重试 + 定时 reconcile |
| 跨资源类型绑定失败 | 中 | 数据不一致 | 幂等校验 + 回滚机制 |
| 权限配置错误 | 高 | 安全风险 | 单元测试 + 安全审计 |
| 删除误操作 | 中 | 数据丢失 | 软删除 + 回收站 + 二次确认 |
| 并发操作冲突 | 中 | 数据不一致 | 乐观锁 + 事务控制 |
| Agent 通信故障 | 高 | 监控失效 | 心跳检测 + 自动重连 |
