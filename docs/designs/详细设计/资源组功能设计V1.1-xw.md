## 1. 引言

### 1.1 目的

本文档旨在详细描述 Websoft9 平台中**资源组（Resource Group）**功能的详细设计方案，包括：

- 明确资源组的业务价值与功能边界
- 定义清晰的技术架构与模块职责
- 规范数据模型、接口契约与业务规则
- 指导开发、测试与运维团队高效协作落地

通过本文档，确保资源组功能在平台中实现：
- **资源分类管理**：按业务场景、部门、环境等维度组织云资源
- **权限隔离**：基于资源组实现细粒度访问控制
- **配额管理**：限制资源使用量，避免资源滥用
- **成本核算**：按资源组统计资源使用成本
- **批量运维**：对资源组内资源执行批量管理操作

### 1.2 范围

本设计文档覆盖以下内容：

**功能范围：**
- 资源组的完整生命周期管理（创建、查询、更新、删除、冻结/解冻）
- 资源绑定与解绑（主机、容器、数据库、网络、存储等多种资源类型）
- 成员管理与权限控制（添加、移除、角色分配）
- 配额管理与监控（设置、校验、预警、调整）
- 标签与元数据管理
- 审计日志与操作记录

**技术范围：**
- Controller → Service → Repository → Model 四层架构设计
- RESTful API 接口定义与 gRPC 服务接口
- 数据库表结构与索引设计
- 权限校验与 RBAC 集成
- 缓存策略与性能优化
- 监控指标与告警规则

**不包含内容：**
- 具体资源类型（主机、容器等）的内部实现细节
- 项目（Project）模块的设计（作为依赖模块）
- 用户与权限系统的底层实现（基于现有 RBAC）
- 前端界面的详细交互设计（仅提供原型参考）

### 1.3 背景

在 Websoft9 云应用管理平台中，用户需要管理大量跨云、跨地域的异构资源。随着业务规模扩展，资源管理面临以下挑战：

**业务痛点：**
- **资源分散**：资源分布在不同云厂商、不同项目，难以统一管理
- **权限混乱**：缺乏细粒度的资源访问控制，存在安全风险
- **配额失控**：无法有效限制资源使用量，导致成本超支
- **运维低效**：批量运维操作复杂，缺乏统一的资源视图
- **成本不清**：无法按业务维度统计资源使用成本

**解决方案：**
资源组作为平台中资源的逻辑集合单元，提供：
- 按业务场景、部门、环境等维度组织资源
- 基于资源组的细粒度权限控制
- 配额管理与超限预警
- 批量操作与统一视图
- 成本统计与分摊

**平台定位：**
资源组是 Websoft9 平台**项目驱动架构**的重要组成部分：
- **项目（Project）**：顶层资源容器，提供项目级隔离
- **资源组（Resource Group）**：项目内的资源集合单元，提供资源分类与配额管理
- **资源（Resource）**：具体的资源实例（主机、容器实例、数据库等）

## 2. 功能概述

### 2.1 功能定位

资源组在 Websoft9 平台中的定位：

```
平台层（Platform）
    ↓
项目层（Project）- 顶层资源容器，提供项目级隔离
    ↓
资源组层（Resource Group）- 资源逻辑集合，提供分类与配额管理
    ↓
资源层（Resource）- 具体资源实例（主机、容器、数据库等）
```

**核心价值：**
- **资源分类**：按业务维度组织资源，提供清晰的资源视图
- **权限隔离**：基于资源组实现细粒度的访问控制
- **配额管理**：限制资源组可使用的资源量，避免资源滥用
- **成本核算**：按资源组统计资源使用成本，支持成本分摊
- **批量运维**：对资源组内资源执行批量管理操作

### 2.2 核心特性

| 特性 | 描述 | 业务价值 |
|------|------|---------|
| **多资源类型支持** | 统一管理主机、容器、数据库、网络、存储等多种资源类型 | 提供统一的资源管理视图 |
| **灵活的配额策略** | 支持 CPU、内存、存储、实例数等多维度配额限制 | 精细化资源使用控制 |
| **细粒度权限控制** | 基于角色的访问控制（Owner、Maintainer、Viewer） | 保障资源访问安全 |
| **完整的生命周期管理** | 支持创建、查询、更新、删除、冻结/解冻等完整操作 | 满足全场景管理需求 |
| **实时监控与告警** | 监控配额使用情况，超限自动告警 | 及时发现资源使用异常 |
| **审计日志** | 记录所有操作历史，支持合规审计 | 满足安全合规要求 |
| **标签与元数据** | 支持自定义标签，便于分类与检索 | 提升资源管理效率 |

### 2.3 目标用户/使用场景

**目标用户：**

| 用户角色 | 使用场景 | 核心需求 |
|---------|---------|---------|
| **平台管理员** | 管理所有项目的资源组 | 全局资源视图、配额管理、审计监控 |
| **项目管理员** | 管理项目内的资源组 | 资源分类、成员管理、配额分配 |
| **开发团队** | 使用开发环境资源组 | 快速获取资源、自助管理、隔离测试 |
| **运维团队** | 管理生产环境资源组 | 批量运维、监控告警、成本优化 |
| **业务团队** | 按业务线管理资源组 | 成本核算、资源申请、权限管理 |

**典型使用场景：**

1. **环境隔离场景**
   - 创建"开发环境"、"测试环境"、"生产环境"资源组
   - 为不同环境设置不同的配额策略
   - 开发团队仅能访问开发环境资源组

2. **业务线隔离场景**
   - 按业务线创建资源组（如"电商业务"、"金融业务"）
   - 不同业务线的资源完全隔离
   - 按资源组统计各业务线的资源成本

3. **团队协作场景**
   - 为团队创建共享资源组
   - 团队成员按角色获得不同权限
   - 支持跨团队的资源共享与协作

4. **成本管理场景**
   - 按部门或项目创建资源组
   - 设置配额限制，控制成本
   - 按资源组生成成本报告，支持成本分摊

5. **批量运维场景**
   - 将同类型资源加入资源组
   - 批量执行启动、停止、重启等操作
   - 统一配置监控告警规则

### 2.4 功能详情

#### 2.4.1 资源组管理

**功能列表：**
- 创建资源组：定义名称、描述、配额、标签等信息
- 查询资源组列表：支持分页、筛选、搜索
- 查询资源组详情：展示基础信息、配额使用、资源列表、成员列表
- 更新资源组：修改名称、描述、标签等信息
- 调整配额：增加或减少资源组的配额限制
- 冻结资源组：禁止资源组的所有写操作，仅允许查询
- 解冻资源组：恢复资源组的正常操作
- 删除资源组：软删除资源组，支持恢复（需先解绑所有资源）

**业务规则：**
- 资源组名称在项目内唯一，长度 3-64 字符
- 资源组配额不能超过所属项目的配额
- 删除资源组前必须先解绑所有资源
- 冻结状态下仅允许查询操作，不允许修改
- 软删除后保留 30 天，期间可恢复

#### 2.4.2 资源绑定管理

**功能列表：**
- 绑定资源：将资源加入资源组
- 批量绑定：一次性绑定多个资源
- 解绑资源：将资源从资源组移除
- 批量解绑：一次性解绑多个资源
- 查询资源列表：查看资源组内的所有资源
- 资源筛选：按资源类型、状态筛选

**业务规则：**
- 单个资源只能属于一个资源组
- 绑定资源后，配额使用量不能超过配额限制
- 资源必须处于可用状态才能绑定
- 绑定/解绑操作需要资源的管理权限
- 解绑资源不删除资源本身

| Feature 名称 | 依赖原因 | 依赖接口 | 必需/可选 |
|-------------|---------|---------|----------|

| **用户与权限（RBAC）** | 成员管理与权限校验 | `GET /api/v1/users/{id}`<br>`POST /api/v1/permissions/check` | 必需 |
| **审计服务（Audit）** | 操作日志记录 | `POST /api/v1/audit/logs` | 必需 |

### 3.3 基础设施依赖

| 基础设施 | 用途 | 配置要求 |
|---------|------|---------|
| **MySQL/PostgreSQL** | 存储资源组元数据、绑定关系、成员信息、审计日志 | 版本 ≥ 8.0（MySQL）<br>版本 ≥ 12（PostgreSQL） |
| **Redis** | 缓存配额使用情况、会话信息 | 版本 ≥ 6.0<br>持久化：RDB + AOF |
| **InfluxDB** | 存储监控指标、时序数据 | 版本 ≥ 2.0 |
| **消息队列** | 异步任务处理、事件通知 | Redis Pub/Sub 或 RabbitMQ |
| **对象存储** | 存储审计日志归档文件 | S3 兼容接口 |

### 3.4 依赖 Feature 缺失时的模拟方案

#### 3.4.1 监控服务缺失

**影响：**
- 无法实时监控配额使用情况
- 无法触发配额告警

**模拟方案：**
- 在资源绑定/解绑时，同步计算配额使用量并缓存到 Redis
- 定时任务（每 5 分钟）扫描所有资源组，重新计算配额使用量
- 配额使用率超过阈值时，写入日志并发送邮件通知

#### 3.4.2 通知服务缺失

**影响：**
- 无法发送成员邀请通知
- 无法发送告警通知

**模拟方案：**
- 记录通知内容到数据库（notifications 表）
- 用户登录后，主动拉取未读通知
- 提供邮件发送工具类，直接发送邮件

#### 3.4.3 审计服务缺失

**影响：**
- 无法统一记录操作日志
- 无法进行合规审计

**模拟方案：**
- 在 Service 层捕获所有操作，写入本地审计日志表
- 提供审计日志查询接口
- 定期导出日志文件到对象存储

## 6. API 与契约

### 6.1 总则

**API 设计原则：**

1. **RESTful 风格**：遵循 REST 架构风格，使用标准 HTTP 方法
2. **统一响应格式**：所有 API 返回统一的 JSON 格式
3. **版本控制**：API 路径包含版本号（如 `/api/v1/`）
4. **认证授权**：所有 API 需要 JWT 认证，基于 RBAC 进行权限校验
5. **错误处理**：返回明确的错误码和国际化错误信息
6. **幂等性**：PUT、DELETE 操作保证幂等性

## 9. 数据模型与存储设计

### 9.1 数据架构概述

资源组模块采用关系型数据库（MySQL/PostgreSQL）存储核心数据，Redis 存储缓存数据。

**数据存储分层：**

```
┌─────────────────────────────────────────────────────┐
│              应用层（Service Layer）                 │
└─────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────┐
│            Repository 层（Data Access）              │
├──────────────────┬──────────────────────────────────┤
│ GORM ORM         │ Redis Client                     │
└──────────────────┴──────────────────────────────────┘
         ↓                           ↓
┌─────────────────────┐    ┌─────────────────────────┐
│  MySQL/PostgreSQL   │    │        Redis            │
│  (主数据存储)       │    │     (缓存存储)          │
├─────────────────────┤    ├─────────────────────────┤
│ - resource_groups   │    │ - 资源组信息缓存        │
│ - rg_bindings       │    │ - 配额使用量缓存        │
│ - rg_members        │    │ - 成员列表缓存          │
│ - rg_audits         │    │ - 资源列表缓存          │
└─────────────────────┘    └─────────────────────────┘
```

**数据一致性保证：**

1. **主库数据为准**：缓存仅作为性能优化，以主库数据为准
2. **缓存失效策略**：写操作时删除相关缓存，下次读取时重新加载
3. **分布式锁**：关键操作（如配额校验）使用 Redis 分布式锁
4. **事务处理**：多表操作使用数据库事务保证一致性

```go
// filepath: webox/api-service/internal/repository/resource_group_batch.go
package repository

import (
    "context"
    "gorm.io/gorm"
)

// BatchCreateBindings 批量创建绑定关系（事务）
func (r *ResourceGroupRepositoryImpl) BatchCreateBindings(
    ctx context.Context,
    groupID int64,
    resources []*ResourceValidationResult,
) (*dto.BatchOperationResult, error) {
    result := &dto.BatchOperationResult{
        SuccessCount:  0,
        FailedCount:  0,
        Results:      make([]*dto.OperationResult, 0, len(resources)),
    }
    
    // 开启事务
    err := r.db.Transaction(func(tx *gorm.DB) error {
        for _, res := range resources {
            binding := &model.ResourceGroupBinding{
                ResourceGroupID: groupID,
                ResourceID:      res.ResourceID,
                ResourceType:    res.ResourceType,
                ResourceName:    res.ResourceName,
                CPUCores:        &res.Specs.CPUCores,
                MemoryMB:        &res.Specs.MemoryMB,
                StorageGB:       &res.Specs.StorageGB,
                Status:          constants.ResourceGroupStatusActive,
                CreatedBy:       getUserID(ctx),
            }
            
            // 插入绑定记录
            if err := tx.Create(binding).Error; err != nil {
                result.FailedCount++
                result.Results = append(result.Results, &dto.OperationResult{
                    ResourceID: res.ResourceID,
                    Status:     "failed",
                    Error:      err.Error(),
                })
                return err // 事务回滚
            }
            
            result.SuccessCount++
            result.Results = append(result.Results, &dto.OperationResult{
                ResourceID: res.ResourceID,
                Status:     "success",
                BindingID:  binding.ID,
            })
        }
        
        return nil
    })
    
    if err != nil {
        return nil, err
    }
    
    return result, nil
}
```

```go
// filepath: webox/api-service/internal/service/resource_group_unbind.go
package service

// UnbindResource 解绑资源
func (s *ResourceGroupServiceImpl) UnbindResource(
    ctx context.Context,
    groupID int64,
    resourceID string,
) error {
    // 1. 权限校验
    if err := s.checkPermission(ctx, groupID, "unbind_resource"); err != nil {
        return err
    }
    
    // 2. 查询绑定关系
    binding, err := s.bindingRepo.GetByResourceID(ctx, resourceID)
    if err != nil {
        return errors.ErrResourceNotFound
    }
    
    if binding.ResourceGroupID != groupID {
        return errors.New("资源不属于该资源组")
    }
    
    // 3. 检查资源依赖
    if err := s.checkResourceDependencies(ctx, resourceID); err != nil {
        return err
    }
    
    // 4. 获取分布式锁
    lockKey := fmt.Sprintf("rg:lock:unbind:%d", groupID)
    lock := s.getLock(lockKey, 10*time.Second)
    if err := lock.Acquire(ctx); err != nil {
        return errors.New("操作繁忙，请稍后重试")
    }
    defer lock.Release(ctx)
    
    // 5. 执行解绑（事务）
    if err := s.repo.UnbindResource(ctx, groupID, resourceID); err != nil {
        return err
    }
    
    // 6. 异步清除缓存和发送通知
    go s.afterUnbind(context.Background(), groupID, resourceID)
    
    return nil
}

// checkResourceDependencies 检查资源依赖
func (s *ResourceGroupServiceImpl) checkResourceDependencies(
    ctx context.Context,
    resourceID string,
) error {
    // 查询是否有其他资源依赖该资源
    dependencies, err := s.resourceClient.GetDependencies(ctx, resourceID)
    if err != nil {
        return err
    }
    
    if len(dependencies) > 0 {
        return errors.New("资源存在依赖关系，请先解除依赖")
    }
    
    return nil
}
```

```go
// filepath: webox/api-service/internal/repository/resource_group_unbind.go
package repository

// UnbindResource 解绑资源（事务）
func (r *ResourceGroupRepositoryImpl) UnbindResource(
    ctx context.Context,
    groupID int64,
    resourceID string,
) error {
    return r.db.Transaction(func(tx *gorm.DB) error {
        // 1. 查询绑定信息（用于回收配额）
        var binding model.ResourceGroupBinding
        if err := tx.Where("resource_group_id = ? AND resource_id = ? AND deleted_at IS NULL", 
            groupID, resourceID).First(&binding).Error; err != nil {
            return err
        }
        
        // 2. 软删除绑定记录
        if err := tx.Delete(&binding).Error; err != nil {
            return err
        }
        
        // 3. 更新配额使用量（减少）
        if err := r.updateQuotaUsage(tx, groupID, &binding, false); err != nil {
            return err
        }
        
        return nil
    })
}
```
