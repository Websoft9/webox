## 1. 引言

### 1.1 目的

本文档旨在详细描述 Websoft9 平台密钥管理功能的设计方案，包括 API 接口定义、数据模型、业务逻辑以及实现要点，为开发团队提供清晰的实现指南，为测试团队提供验收标准。

### 1.2 范围

本文档涵盖密钥管理功能的完整设计，包括：
- 密钥的创建、查询、更新和删除操作
- 基于项目的密钥隔离与权限控制
- 密钥的安全存储与加密
- 密钥与应用的关联关系管理

### 1.3 背景

在云应用管理场景中，用户需要管理各类敏感凭证信息（如 API Key、数据库密码、SSL 证书等）。密钥管理功能为用户提供统一的凭证存储和管理能力，确保敏感信息的安全性和可追溯性。该功能是应用部署、配置管理等功能的基础支撑。

## 2. 功能概述

### 2.1 功能定位

密钥管理是 Websoft9 平台的核心安全功能之一，提供集中化的凭证管理能力。作为平台的基础设施层功能，为应用部署、配置管理、自动化运维等上层功能提供安全的密钥存储和访问服务。

### 2.2 核心特性

- **集中管理**：统一存储和管理各类敏感凭证信息
- **项目隔离**：基于项目的多租户隔离机制
- **安全存储**：敏感信息加密存储，确保数据安全
- **灵活分类**：支持多种密钥类型和自定义分类
- **关联追踪**：记录密钥与应用的关联关系
- **操作审计**：完整的操作日志记录

### 2.3 目标用户/使用场景

**目标用户**：
- 平台管理员：管理平台级密钥资源
- 项目管理员：管理项目范围内的密钥
- 应用开发者：使用密钥进行应用部署和配置

**使用场景**：
1. 应用部署时需要使用数据库密码、API Key 等凭证
2. 配置外部服务集成时需要存储第三方服务的访问凭证
3. SSL 证书管理和自动续期
4. 自动化运维脚本中的凭证管理
5. 多环境配置的密钥切换

### 2.4 功能详情

密钥管理功能提供以下核心能力：

1. **密钥 CRUD 操作**：支持创建、查询、更新和删除密钥
2. **密钥类型管理**：支持多种预定义类型和自定义类型
3. **项目级隔离**：每个密钥归属于特定项目，实现资源隔离
4. **权限控制**：基于 RBAC 的细粒度权限管理
5. **关联管理**：追踪密钥被哪些应用使用
6. **批量操作**：支持批量创建、更新和删除密钥
7. **搜索过滤**：支持多维度的密钥检索

## 3. 依赖关系

### 3.1 依赖 Feature 列表

| Feature 名称 | 依赖说明 | 依赖程度 |
|-------------|---------|---------|
| 项目管理 | 密钥归属于项目，需要项目 ID 和权限校验 | 强依赖 |
| 用户认证 | 需要用户身份认证和 JWT Token 验证 | 强依赖 |
| 权限管理 | 需要基于 RBAC 的权限校验 | 强依赖 |
| 操作审计 | 记录密钥操作日志 | 弱依赖 |

### 3.2 依赖服务与接口契约

**项目管理服务**：
- 接口：`ProjectService.GetProject(projectID string) (*model.Project, error)`
- 用途：验证项目是否存在，获取项目信息
- 契约：返回项目详情或 404 错误

**权限管理服务**：
- 接口：`AuthMiddleware.CheckProjectPermission()`
- 用途：校验用户对项目的操作权限
- 契约：无权限时返回 403 错误

### 3.3 基础设施依赖

- **数据库**：MySQL 8.0+ 或 PostgreSQL 12+，用于持久化存储
- **Redis**：用于缓存密钥类型等静态配置
- **加密服务**：AES-256 加密算法，用于敏感信息加密

### 3.4 依赖 Feature 缺失时的模拟方案

**项目管理缺失时**：
- 使用默认项目 ID（default-project）
- 所有密钥归属于默认项目
- 跳过项目存在性验证

**权限管理缺失时**：
- 允许所有已认证用户进行密钥操作
- 记录操作日志以便后续审计

## 4. 业务目标与用户故事

### 4.1 业务目标

1. **提升安全性**：集中管理敏感凭证，避免明文存储和传输
2. **提高效率**：简化密钥管理流程，支持快速检索和复用
3. **确保合规**：提供完整的操作审计，满足安全合规要求
4. **降低风险**：通过权限控制和加密存储，降低数据泄露风险

### 4.2 用户故事

**Story 1**：作为项目管理员，我希望能够创建和管理项目内的密钥，以便在部署应用时安全地使用这些凭证。

**验收标准**：
- 能够创建不同类型的密钥（数据库密码、API Key 等）
- 密钥信息加密存储，不可明文查看
- 可以编辑密钥的名称、描述等非敏感信息

**Story 2**：作为应用开发者，我希望能够快速查找可用的密钥，以便在配置应用时选择合适的凭证。

**验收标准**：
- 支持按名称、类型、标签等条件搜索密钥
- 查询结果分页显示
- 可以查看密钥的基本信息和使用情况

**Story 3**：作为平台管理员，我希望了解密钥的使用情况，以便及时清理未使用的密钥。

**验收标准**：
- 能够查看密钥被哪些应用使用
- 删除密钥时提示关联的应用
- 提供密钥使用统计报表

## 6. API 与契约

### 6.1 总则

- **基础路径**：`/api/v1/secret-keys`
- **认证方式**：JWT Token（通过 `Authorization: Bearer <token>` 传递）
- **权限要求**：所有接口需要项目级权限校验
- **响应格式**：统一 JSON 格式，遵循平台响应规范
- **错误处理**：使用统一错误码和国际化错误消息

### 6.2 API 接口汇总

| 序号 | 方法 | 路径 | 功能 | 权限 |
|-----|------|-----|------|------|
| 1 | GET | `/api/v1/secret-keys` | 获取密钥列表 | project:secret:read |
| 2 | POST | `/api/v1/secret-keys/text` | 创建文本密钥 | project:secret:create |
| 3 | POST | `/api/v1/secret-keys/file` | 创建文件密钥 | project:secret:create |
| 4 | GET | `/api/v1/secret-keys/:id` | 查询密钥详情 | project:secret:read |
| 5 | PUT | `/api/v1/secret-keys/:id` | 更新密钥 | project:secret:update |
| 6 | DELETE | `/api/v1/secret-keys/:id` | 删除密钥 | project:secret:delete |
| 7 | GET | `/api/v1/secret-keys/export` | 导出密钥 | project:secret:read |

### 6.3 核心 API 详细说明

#### 6.3.1 获取密钥列表

**接口定义**：
- **方法**：GET
- **路径**：`/api/v1/secret-keys`
- **功能**：查询密钥列表，支持过滤和分页

**查询参数**：

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|-------|------|-----|--------|------|
| page | integer | 否 | 1 | 页码 |
| page_size | integer | 否 | 20 | 每页数量 |
| key_type | string | 否 | - | 密钥类型（TEXT/ACCOUNT/FILE） |
| keyword | string | 否 | - | 关键词，对密钥名称和描述进行模糊查询 |
| resource_code | string | 否 | - | 资源编码，查询该资源关联的所有密钥 |

**请求示例**：
```
GET /api/v1/secret-keys?page=1&page_size=20&key_type=ACCOUNT&keyword=数据库
```

**响应示例**（成功 - 200 OK）：
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "items": [
      {
        "id": 1,
        "name": "数据库连接密钥",
        "key_type": "ACCOUNT",
        "description": "MySQL数据库连接密钥",
        "is_encrypted": true,
        "authorized_users": [1, 2],
        "authorized_groups": [1],
        "expires_at": "2025-04-01T00:00:00Z",
        "owner_id": 1,
        "created_at": "2024-10-01T00:00:00Z",
        "updated_at": "2025-07-15T10:30:00Z"
      }
    ],
    "pagination": {
      "page": 1,
      "page_size": 20,
      "total": 1,
      "total_pages": 1
    }
  }
}
```

**业务规则**：
1. 仅返回用户有权限访问的密钥
2. 密钥值不在列表中返回，确保安全
3. 支持多条件组合查询
4. 默认按创建时间倒序排列
5. 当 `resource_code` 不为空时，关联 `secret_references` 表查询该资源关联的所有密钥

**错误码**：
- `400`：参数验证失败
- `401`：未认证
- `403`：无权限查看密钥列表
- `500`：服务器内部错误

#### 6.3.2 创建文本密钥

**接口定义**：
- **方法**：POST
- **路径**：`/api/v1/secret-keys/text`
- **功能**：创建文本类型密钥，系统根据字段内容自动判断类型

**请求参数**：

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|-------|------|-----|------|------|
| name | string | 是 | 密钥名称 | "OpenAI API密钥" |
| resource_group_id | integer | 否 | 资源组ID | 1 |
| description | string | 否 | 密钥描述 | "用于调用OpenAI API的密钥" |
| secret_fields | object | 是 | 密钥字段，根据内容自动判断类型 | 见下方示例 |
| authorized_users | array | 否 | 授权用户ID列表 | [1, 2, 3] |
| expires_at | string | 否 | 过期时间 | "2025-12-31T23:59:59Z" |
| resource_code | string | 否 | 资源编码 | "mysql-prod-001" |

**请求示例（TEXT 类型）**：
```json
{
  "name": "OpenAI API密钥",
  "description": "用于调用OpenAI API的密钥",
  "secret_fields": {
    "secret_key": "sk-1234567890abcdef"
  },
  "expires_at": "2025-12-31T23:59:59Z"
}
```

**请求示例（ACCOUNT 类型）**：
```json
{
  "name": "数据库账号",
  "description": "MySQL数据库管理员账号",
  "secret_fields": {
    "username": "root",
    "password": "123456"
  },
  "resource_code": "mysql-prod-001"
}
```

**响应示例**（成功 - 200 OK）：
```json
{
  "code": 200,
  "message": "密钥创建成功",
  "data": {
    "id": 1,
    "name": "OpenAI API密钥",
    "key_type": "TEXT",
    "description": "用于调用OpenAI API的密钥",
    "is_encrypted": true,
    "expires_at": "2025-12-31T23:59:59Z",
    "owner_id": 1,
    "created_at": "2025-01-15T10:30:00Z",
    "updated_at": "2025-01-15T10:30:00Z"
  }
}
```

**业务规则**：
1. 系统根据 `secret_fields` 内容自动判断密钥类型：
   - 包含 `secret_key` 字段时，识别为 TEXT 类型
   - 包含 `username` 和 `password` 字段时，识别为 ACCOUNT 类型
2. 密钥字段内容加密存储
3. 创建时自动记录创建者信息
4. 如果提供 `resource_code`，自动创建关联记录

**错误码**：
- `400`：参数验证失败或密钥名称重复
- `401`：未认证
- `403`：无权限创建密钥
- `500`：服务器内部错误

#### 6.3.3 创建文件密钥

**接口定义**：
- **方法**：POST
- **路径**：`/api/v1/secret-keys/file`
- **功能**：创建文件类型密钥（如证书、密钥文件等）

**请求参数（multipart/form-data）**：

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|-------|------|-----|------|------|
| name | string | 是 | 密钥名称 | "SSL证书" |
| file | file | 是 | 文件内容（证书、密钥等） | - |
| secret_fields | string | 否 | 密钥字段（JSON字符串），可包含 password 等 | '{"password":"123456"}' |
| description | string | 否 | 密钥描述 | "生产环境SSL证书" |
| resource_group_id | integer | 否 | 资源组ID | 1 |
| expires_at | string | 否 | 过期时间 | "2026-01-15T00:00:00Z" |
| authorized_users | array | 否 | 授权用户ID列表 | [1, 2] |
| resource_code | string | 否 | 资源编码 | "nginx-prod-001" |

**请求示例**：
```
POST /api/v1/secret-keys/file
Content-Type: multipart/form-data

--boundary
Content-Disposition: form-data; name="name"

SSL证书
--boundary
Content-Disposition: form-data; name="file"; filename="ssl-certificate.pem"
Content-Type: application/x-pem-file

[文件内容]
--boundary
Content-Disposition: form-data; name="description"

生产环境SSL证书
--boundary
Content-Disposition: form-data; name="expires_at"

2026-01-15T00:00:00Z
--boundary--
```

**响应示例**（成功 - 200 OK）：
```json
{
  "code": 200,
  "message": "文件密钥创建成功",
  "data": {
    "id": 2,
    "name": "SSL证书",
    "key_type": "FILE",
    "description": "生产环境SSL证书",
    "is_encrypted": true,
    "secret_fields": {
      "filename": "ssl-certificate.pem",
      "password": "***"
    },
    "expires_at": "2026-01-15T00:00:00Z",
    "owner_id": 1,
    "created_at": "2025-01-15T10:35:00Z",
    "updated_at": "2025-01-15T10:35:00Z"
  }
}
```

**业务规则**：
1. 文件类型密钥自动识别为 FILE 类型
2. 文件内容原文存储（加密）
3. `secret_fields` 自动生成，包含 `filename` 和可选的 `password` 字段
4. 支持多种文件格式（.pem, .key, .crt, .p12 等）
5. 文件大小限制：不超过 10MB

**错误码**：
- `400`：参数验证失败、文件格式不支持或文件过大
- `401`：未认证
- `403`：无权限创建密钥
- `500`：服务器内部错误

#### 6.3.5 更新密钥

**接口定义**：
- **方法**：PUT
- **路径**：`/api/v1/secret-keys/:id`
- **功能**：更新指定密钥的信息

**路径参数**：

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|-------|------|-----|------|------|
| id | integer | 是 | 密钥 ID | 1 |

**请求参数**：

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|-------|------|-----|------|------|
| name | string | 否 | 密钥名称 | "更新后的密钥名称" |
| description | string | 否 | 密钥描述 | "更新后的描述" |
| expires_at | string | 否 | 过期时间 | "2026-12-31T23:59:59Z" |

**请求示例**：
```json
{
  "name": "数据库连接密钥-生产环境",
  "description": "更新后的MySQL数据库连接密钥",
  "expires_at": "2026-04-01T00:00:00Z"
}
```

**响应示例**（成功 - 200 OK）：
```json
{
  "code": 200,
  "message": "密钥更新成功",
  "data": {
    "id": 1,
    "name": "数据库连接密钥-生产环境",
    "key_type": "ACCOUNT",
    "description": "更新后的MySQL数据库连接密钥",
    "is_encrypted": true,
    "expires_at": "2026-04-01T00:00:00Z",
    "owner_id": 1,
    "created_at": "2024-10-01T00:00:00Z",
    "updated_at": "2025-01-15T11:00:00Z"
  }
}
```

**业务规则**：
1. 支持部分字段更新，未传递的字段保持不变
2. 不支持更新密钥类型（key_type）
3. 不支持通过此接口更新密钥值，需要重新创建
4. 记录更新操作到审计日志
5. 更新时间自动更新

**错误码**：
- `400`：参数验证失败或名称重复
- `401`：未认证
- `403`：无权限更新密钥
- `404`：密钥不存在
- `500`：服务器内部错误

#### 6.3.6 删除密钥

**接口定义**：
- **方法**：DELETE
- **路径**：`/api/v1/secret-keys/:id`
- **功能**：删除指定密钥

**路径参数**：

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|-------|------|-----|------|------|
| id | integer | 是 | 密钥 ID | 1 |

**请求示例**：
```
DELETE /api/v1/secret-keys/1
```

**响应示例**（成功 - 200 OK）：
```json
{
  "code": 200,
  "message": "密钥删除成功",
  "data": null
}
```

**响应示例**（失败 - 409 Conflict，存在关联）：
```json
{
  "code": 409,
  "message": "无法删除密钥：该密钥正在被资源使用",
  "data": {
    "associated_resources": ["mysql-prod-001", "mysql-dev-001"],
    "resource_count": 2
  }
}
```

**业务规则**：
1. 删除前检查密钥是否被资源引用
2. 如果存在关联资源，不允许删除
3. 删除操作记录到审计日志
4. 物理删除，不支持软删除
5. 同时删除 `secret_references` 表中的关联记录

**错误码**：
- `401`：未认证
- `403`：无权限删除密钥
- `404`：密钥不存在
- `409`：密钥正在被使用，不能删除
- `500`：服务器内部错误

#### 6.3.7 导出密钥

**接口定义**：
- **方法**：GET
- **路径**：`/api/v1/secret-keys/export`
- **功能**：导出密钥列表为文件

**查询参数**：

**请求示例**：

```
GET /api/v1/secret-keys/export?format=csv
```

```
HTTP/1.1 200 OK

Content-Disposition: attachment; filename="secret-keys-20250122.csv"
```

**CSV 文件格式示例**：

**错误码**：

## 10. 实现要点与关键数据流

### 10.1 批量操作技术实现架构

无批量操作

### 10.2 密钥加密实现逻辑

**加密方案**：
- 算法：AES-256-GCM
- 密钥来源：账号密码或者KEY
- IV（初始化向量）：每次加密随机生成，与密文一起存储

**加密流程**：
```
1. 获取加密密钥
   └─ 从配置或环境变量读取
   
2. 生成随机IV
   └─ 使用加密安全的随机数生成器
   
3. 执行加密
   ├─ 使用AES-256-GCM算法
   └─ 生成密文和认证标签
   
4. 存储到数据库
```

**解密流程**：
```
1. 从数据库读取加密数据
   
2. 获取解密密钥
   └─ 与加密使用相同的密钥
   
3. 执行解密
   ├─ 验证认证标签
   └─ 解密得到明文
   
4. 返回明文密钥值
```

## 12. 风险与应对

### 12.1 风险清单

| 风险类型 | 风险描述 | 影响等级 | 发生概率 |
|---------|---------|---------|---------|
| 安全风险 | 密钥值泄露导致敏感信息暴露 | 高 | 低 |
| 性能风险 | 批量操作导致数据库压力过大 | 中 | 中 |
| 依赖风险 | 加密库存在安全漏洞 | 高 | 低 |
| 操作风险 | 误删除密钥导致业务中断 | 高 | 中 |
| 兼容风险 | 数据库迁移导致数据丢失 | 中 | 低 |

### 12.2 风险应对策略

**安全风险应对**：
- 使用成熟的加密算法和库
- 严格的权限控制和审计
- 定期安全审计和渗透测试
- 密钥值访问需要额外权限验证

**性能风险应对**：
- 限制批量操作的数量
- 使用数据库连接池
- 合理设置索引
- 引入缓存机制减轻数据库压力

**依赖风险应对**：
- 选择广泛使用的加密库
- 定期更新依赖包
- 关注安全公告
- 建立应急响应机制

**操作风险应对**：
- 删除前检查关联关系
- 提供二次确认机制
- 支持操作回滚
- 完整的操作审计日志

**兼容风险应对**：
- 数据迁移前完整备份
- 编写迁移脚本并充分测试
- 提供数据恢复方案
- 灰度发布，逐步迁移
