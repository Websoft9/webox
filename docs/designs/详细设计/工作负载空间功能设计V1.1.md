## 1. 需求

### 1.1 是什么？

<!-- 简要描述本功能模块的定位和作用，一句话说明该功能在系统中的角色。 -->

工作负载空间（Workload Space）是项目中的虚拟存储区域，用于管理应用的编排文件和工作负载定义。它提供统一的接口，支持多种存储后端（如本地文件夹、Git仓库），实现工作负载的版本控制和GitOps自动化部署。作为项目管理的子模块，工作负载空间支撑 Websoft9 平台的工作流驱动和应用生命周期管理。

### 1.2 解决什么问题？

工作负载空间旨在解决企业在云应用管理中工作负载文件分散、版本控制缺失、协作困难的问题：

1. **文件管理混乱**：工作负载编排文件（如 Docker Compose、K8s YAML）散落在项目文件夹中，难以组织和维护
2. **版本控制缺失**：缺乏对工作负载文件的版本管理，无法追溯变更历史和回滚错误配置
3. **协作效率低下**：多用户并发编辑工作负载文件时，容易产生冲突和覆盖，缺乏协作机制
4. **GitOps 支持不足**：无法实现工作负载变更的自动化部署和 CI/CD 集成
5. **存储灵活性不足**：仅依赖本地文件夹，无法支持分布式团队的远程协作和多环境管理
6. **部署依赖高**：强制要求 Git 服务，增加小规模部署的基础设施成本

#### 1.2.1 业务目标

- **存储统一率**：实现 100% 的工作负载文件统一管理，避免文件分散存储导致的混乱
- **版本控制覆盖率**：在 Git 模式下提供完整的版本控制功能，支持 GitOps 模式的自动化部署
- **协作效率提升**：通过多用户协作和冲突解决机制，提升团队开发效率
- **部署自动化率**：实现工作负载变更的自动化部署，减少手动干预
- **存储灵活性**：支持文件夹和 Git 仓库两种存储模式，满足不同场景和规模的部署需求
- **降低部署门槛**：文件夹模式下无需额外基础设施，单机部署时间缩短

#### 1.2.2 用户故事

| 编号 | 用户角色 | 用户目标 | 业务价值 |
|------|---------|---------|---------|
| WS-US-001 | 项目开发者 | 快速上传和管理工作负载编排文件 | 简化应用部署流程，提升开发效率 |
| WS-US-002 | 项目 Owner | 查看工作负载文件的变更历史和差异 | 便于问题排查和版本回溯 |
| WS-US-003 | DevOps 工程师 | 通过 Git 提交触发自动化部署 | 实现 GitOps，减少手动部署错误 |
| WS-US-004 | 小型企业用户 | 在文件夹模式下管理工作负载（无 Git 环境） | 降低基础设施依赖，快速上手 |
| WS-US-005 | 团队成员 | 协作编辑工作负载文件并解决冲突 | 提升团队协作质量和效率 |
| WS-US-006 | 平台管理员 | 从文件夹模式迁移到 Git 模式 | 支持从简单部署平滑升级到 GitOps |

### 1.3 功能需求

#### 1.3.1 创建工作负载空间

**核心功能：**
- **空间类型选择**：支持文件夹模式和 Git 模式两种存储类型
  - **文件夹模式**：使用本地文件系统存储，适合单机部署或小规模场景
  - **Git 模式**：集成 Gitea/GitLab，实现 GitOps 和版本控制
- **自动初始化**：
  - 文件夹模式：在项目目录下创建 `workloads/` 子目录，初始化基础结构
  - Git 模式：调用 Gitea API 创建专用仓库，推送工作负载模板
- **权限继承**：自动继承项目的访问控制策略和成员权限
- **模板支持**：提供常用工作负载模板（Docker Compose、Kubernetes YAML 等）

**预期行为：**
- 工作负载空间与项目一对一绑定，项目创建时自动创建工作负载空间
- 空间类型可以在后续进行切换（文件夹 → Git，需数据迁移）
- 创建失败时自动回滚，避免产生脏数据
- 创建操作记录审计日志

#### 1.3.2 文件管理

**核心功能：**
- **文件列表查看**：展示工作负载空间中的所有文件，支持目录结构展示
- **文件上传/创建**：
  - 支持单个文件上传或批量上传
  - 支持在线创建新文件（选择模板或空白文件）
  - 自动识别文件类型（YAML、JSON、Dockerfile 等）
- **文件在线编辑**：
  - 集成代码编辑器（Monaco Editor），支持语法高亮
  - 提供语法校验和错误提示
  - 支持自动保存和草稿功能
- **文件下载/导出**：
  - 单个文件下载
  - 批量下载（ZIP 压缩包）
  - 导出到本地 Git 仓库
- **文件删除**：删除不需要的工作负载文件，需二次确认
- **文件搜索**：按文件名、内容关键词、文件类型搜索

**预期行为：**
- 支持常见工作负载文件格式：Docker Compose、Kubernetes YAML、Helm Chart、Dockerfile 等
- 文件大小限制：单个文件不超过 10MB
- 文件名命名规范：支持字母、数字、下划线、中划线和点号
- 编辑时自动检测文件冲突（Git 模式）
- 所有文件操作记录审计日志

#### 1.3.3 版本控制（Git 模式）

**核心功能：**
- **提交变更（Commit）**：
  - 将文件修改提交到 Git 仓库
  - 支持填写提交信息（必填）
  - 自动关联操作人和时间戳
- **查看提交历史**：
  - 展示最近的提交记录（时间、作者、提交信息）
  - 支持按时间范围、作者筛选
  - 支持分页查询
- **文件差异查看（Diff）**：
  - 对比文件修改前后的差异
  - 高亮显示新增、删除、修改的行
  - 支持并排对比或统一视图
- **版本回滚**：
  - 回滚到指定的历史提交版本
  - 需要二次确认并填写回滚原因
  - 回滚操作生成新的提交记录
- **分支管理**（可选）：
  - 查看当前分支
  - 切换分支（主要用于多环境场景）

**预期行为：**
- 仅在 Git 模式下可用，文件夹模式不支持版本控制
- 提交操作自动推送到远程 Git 仓库
- 提交历史默认显示最近 50 条记录
- 回滚操作不删除历史记录，保持完整的审计链
- 版本控制操作记录审计日志

#### 1.3.4 工作负载空间类型切换

**核心功能：**
- **从文件夹切换到 Git**：
  - 创建新的 Git 仓库
  - 将文件夹中的文件推送到 Git 仓库
  - 初始化 Git 历史记录
  - 更新工作负载空间配置
- **切换前检查**：
  - 验证 Gitea 服务可用性
  - 检查文件完整性
  - 估算迁移时间和存储空间
- **数据迁移**：
  - 复制所有工作负载文件到 Git 仓库
  - 保留文件时间戳和元数据
  - 生成初始提交记录
- **切换后验证**：
  - 验证文件完整性
  - 测试 Git 仓库可访问性
  - 清理原文件夹数据（可选保留备份）

**预期行为：**
- 切换操作需要 `project:manage` 权限
- 切换过程中工作负载空间只读，禁止文件修改
- 切换失败时自动回滚，保持原有模式
- 切换操作记录完整审计日志
- 暂不支持从 Git 切换回文件夹（单向迁移）

#### 1.3.5 GitOps 集成（Git 模式）

**核心功能：**
- **Webhook 配置**：
  - 自动为 Git 仓库配置 Webhook
  - 监听 Push 事件，触发自动化部署
  - 支持自定义触发条件（如指定分支）
- **自动化部署流程**：
  1. Git 提交触发 Webhook
  2. Websoft9 API 接收通知
  3. 验证提交合法性
  4. 触发工作流引擎执行部署
  5. 更新部署状态
- **部署状态跟踪**：
  - 展示最近的部署记录
  - 显示部署状态（成功/失败/进行中）
  - 提供部署日志查看
- **手动触发部署**：
  - 支持手动触发指定版本的部署
  - 需要填写部署原因

**预期行为：**
- 仅在 Git 模式下可用
- Webhook 自动配置，用户无需手动设置
- 部署失败时发送通知给项目成员
- 部署操作记录审计日志
- 支持部署前的人工审批（可选配置）

#### 1.3.6 工作负载空间配置管理

**核心功能：**
- **空间配置**：
  - 存储类型（文件夹/Git）
  - Git 仓库地址（Git 模式）
  - Webhook URL（Git 模式）
  - 自动部署开关
  - 文件大小限制
- **配置修改**：
  - 支持修改自动部署开关
  - 支持修改文件大小限制
  - 不支持直接修改存储类型（需通过切换功能）
- **配置导出/导入**：
  - 导出工作负载空间配置为 JSON
  - 支持从配置文件导入（用于项目克隆）

**预期行为：**
- 配置存储在项目的 `system_config` 表中
- 配置修改立即生效
- 关键配置修改需要二次确认
- 配置修改记录审计日志

#### 1.3.7 工作负载空间监控与统计

**核心功能：**
- **空间统计**：
  - 文件总数
  - 存储使用量
  - 提交次数（Git 模式）
  - 部署次数（Git 模式）
- **活动记录**：
  - 最近的文件操作记录
  - 最近的提交记录（Git 模式）
  - 最近的部署记录（Git 模式）
- **健康检查**：
  - Git 仓库连接状态（Git 模式）
  - Webhook 状态（Git 模式）
  - 存储空间告警

**预期行为：**
- 统计数据实时计算或定期缓存
- 支持按时间范围查询历史统计
- 存储空间超过 80% 时发送告警
- 统计数据展示在项目详情页
