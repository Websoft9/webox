## 1. 引言

### 1.1 目的

提供统一的 SSL/TLS 证书全生命周期管理功能，支持证书申请、上传、验证、查询、下载和续期，为平台应用提供安全的 HTTPS 访问支撑。

### 1.2 范围

- **功能边界**：证书生命周期管理（申请、上传、验证、查询、续期、吊销）
- **支持范围**：
  - 通过 ACME 协议向 ACME CA 机构 （Let's Encrypt，ZeroSSL）等申请免费证书
  - 生成自签名证书用于测试环境
  - 上传已有的第三方证书
  - HTTP-01 自动验证和 DNS-01 手动验证
  - 证书到期自动提醒与续期
- **非目标**：
  - 不实现证书在目标服务器上的自动部署（由独立部署模块实现）
  - 不实现 DNS 服务商的自动接入（第一版采用手动 DNS 验证）
  - 不涉及网关/代理层的证书配置管理

### 1.3 背景

在 Websoft9 平台中，应用需要通过 HTTPS 提供安全访问。证书管理模块作为安全基础设施层，提供中心化的证书管理能力，支持多种证书来源，降低证书获取和维护成本。

## 2. 功能概述

### 2.1 功能定位

证书管理模块作为 Websoft9 平台的安全基础设施层，提供证书资源的全生命周期管理能力，并对外提供标准化的 API 接口和事件通知机制。

### 2.2 核心特性

- **多源证书支持**：ACME CA （Let's Encrypt）自动申请、自签名证书生成、第三方证书上传
- **灵活验证方式**：HTTP-01 自动验证（验证文件）、DNS-01 手动验证
- **安全存储**：私钥加密存储，证书元数据与实际内容分离
- **自动续期**：基于到期时间的自动续期提醒与执行
- **CA 可配置**：支持多 CA 配置，默认 Let's Encrypt，可扩展其他 ACME CA
- **部署解耦**：提供证书导出接口，不直接参与证书部署

### 2.3 目标用户/使用场景

- **系统管理员**：配置 CA 服务商、管理证书生命周期、查看证书状态
- **应用管理员**：为应用域名申请证书、上传证书、查看证书详情
- **运维人员**：监控证书到期状态、处理续期失败、导出证书用于手动部署
- **开发人员**：生成自签名证书用于开发测试环境

### 2.4 功能详情

1. 【证书查询】

支持分页查询和多条件筛选，查询条件包括：

| 查询条件   | 示例                  | 描述                                     |
| ---------- | --------------------- | ---------------------------------------- |
| 证书名称   | example.com           | 文本输入框，支持证书名称关键词模糊查询   |
| 域名       | www.example.com       | 文本输入框，支持域名模糊查询             |
| 证书状态   | issued                | 下拉选择，支持按状态筛选                 |
| 证书类型   | letsencrypt           | 下拉选择，支持按类型筛选                 |
| 到期时间   | 近30天                | 日期范围选择器，支持按到期时间范围筛选   |
| 创建时间   | 近7天                 | 日期范围选择器，支持按创建时间范围筛选   |

2. 【证书列表】

按照到期时间排序（即将到期的优先），以列表方式展示证书，展示信息包括：

- 证书名称、主域名、附加域名（SAN）
- 证书类型（Let's Encrypt、自签名、上传）
- 证书状态（待验证、已签发、已过期、已吊销）
- 签发时间、到期时间、剩余天数
- CA 提供商、验证方法
- 所属项目、创建人

3. 【证书申请】

通过证书申请向导分步申请证书：

- 【基本信息】填写证书名称、域名列表、选择 CA 提供商
- 【验证方式】选择 HTTP-01 或 DNS-01 验证方法
- 【验证挑战】根据验证方式完成挑战（HTTP 自动托管或 DNS 手动配置）
- 【签发确认】等待证书签发并显示证书信息

4. 【自签名证书生成】

支持快速生成自签名证书：

- 填写域名、有效期、组织信息
- 系统自动生成私钥和自签名证书
- 可直接下载或保存到证书库

5. 【证书上传】

支持上传第三方证书：

- 上传证书文件（PEM 格式）
- 上传私钥文件（PEM 格式，支持加密）
- 上传证书链（可选）
- 系统自动解析证书信息并验证完整性

6. 【证书详情】

点击证书名称进入详情页面，包含：

- 【基本信息】证书名称、域名列表、证书类型、CA 提供商
- 【证书状态】当前状态、签发时间、到期时间、剩余天数
- 【证书内容】证书指纹、序列号、签发者、使用者
- 【验证信息】验证方法、验证状态、验证记录
- 【续期历史】历史续期记录、续期状态

7. 【证书续期】

支持手动和自动续期：

- 手动触发续期操作
- 系统自动检测即将到期的证书并触发续期
- 续期失败时发送通知提醒

8. 【证书导出】

支持导出证书与私钥：

- 下载证书文件（PEM/CRT 格式）
- 下载私钥文件（需权限验证）
- 下载证书链
- 导出为 PKCS#12 格式（.pfx/.p12）

9. 【证书删除/吊销】

支持删除和吊销证书：

- 删除上传的证书（软删除）
- 吊销 ACME 证书（向 CA 发送吊销请求）
- 删除前检查是否有应用正在使用

## 3. 依赖关系

### 3.1 依赖Feature列表

- **用户管理**（强依赖）：证书权限控制和所有者管理
- **项目管理**（强依赖）：证书资源组织和项目资源分配
- **权限管理**（强依赖）：证书操作权限控制
- **密钥管理**（强依赖）：私钥加密存储和管理
- **任务管理**（弱依赖）：异步证书申请和续期任务调度
- **通知管理**（弱依赖）：证书到期提醒、续期失败通知
- **审计日志**（弱依赖）：证书操作审计记录
- **应用管理**（弱依赖）：查询证书使用情况
- **资源组管理**（弱依赖）：证书作为一种资源所归宿的资源组

### 3.2 依赖服务与接口契约

- **认证服务**：JWT Token 验证，API 调用权限检查
- **权限服务**：RBAC 权限验证，操作授权检查
- **密钥管理服务**：私钥加密存储、检索和解密，支持 AES-256 加密
- **审计服务**：操作日志记录，审计事件上报
- **HTTP 托管服务**（可选）：用于 HTTP-01 验证时托管挑战文件

**接口契约示例**：

```go
// 密钥管理服务接口
type SecretService interface {
    // 加密存储私钥
    EncryptAndStore(ctx context.Context, key []byte) (encryptedKey string, err error)
    // 解密私钥
    DecryptKey(ctx context.Context, encryptedKey string) (key []byte, err error)
}

// 审计服务接口
type AuditService interface {
    // 记录证书操作
    LogCertificateOperation(ctx context.Context, event AuditEvent) error
}
```

### 3.3 基础设施依赖

- **MySQL**：证书元数据、CA 配置、验证记录存储
- **Redis**：证书申请任务状态、验证挑战缓存
- **文件存储**（可选）：证书文件备份存储
- **外网访问**：向 Let's Encrypt ACME API 发起请求（acme-v02.api.letsencrypt.org）

### 3.4 依赖 Feature 缺失时的模拟方案

- **任务管理 Feature** 尚在开发中，本阶段证书管理模块使用内置的同步/异步实现来替代真实任务系统。
- API 层仍然返回 task_id、status 等字段，但任务执行由服务内部处理。
- 证书申请和续期任务状态存于 Redis，仅用于前端展示与调试，不具备真正的分布式任务调度能力。
- 未来接入真实任务管理时，将通过相同接口契约替换内部实现，保证调用方无感知。

## 4. 业务目标与用户故事

### 4.1 业务目标

1. **降低证书获取成本**：通过 Let's Encrypt 提供免费 SSL 证书，降低企业 HTTPS 成本
2. **简化证书管理**：提供统一的证书管理界面，减少手动操作和人为错误
3. **提升安全性**：私钥加密存储，操作审计，权限控制
4. **自动化续期**：避免证书过期导致的服务中断

## 5. 模块与职责

### 5.1 模块清单

| 模块名称                  | 核心职责                                   | 交付物                                 |
| ------------------------- | ------------------------------------------ | -------------------------------------- |
| 证书管理服务              | 证书 CRUD 操作、状态管理、生命周期控制     | CertificateService、CertificateRepository |
| ACME 客户端服务           | 与 Let's Encrypt 交互，实现 ACME 协议      | ACMEClientService                      |
| CA 提供商管理服务         | CA 配置管理、多 CA 支持                    | CAProviderService、CAProviderRepository |
| 验证服务                  | 证书验证挑战管理、HTTP-01/DNS-01 验证      | ValidationService、ValidationRepository |
| 自签名证书生成服务        | 生成自签名证书和私钥                       | SelfSignedCertService                  |
| 证书存储服务              | 私钥加密存储、证书文件导出                 | CertStorageService                     |
| 续期管理服务              | 自动续期检测、续期任务调度                 | RenewalService、RenewalRepository      |

### 5.2 服务层架构

```
Controller → Service → Repository → Model
    ↓         ↓          ↓
   DTO    Business    Database/Redis
```

**分层说明**：

- **Controller 层**：接收 HTTP 请求，参数验证，调用 Service 层
- **Service 层**：业务逻辑处理，调用 Repository 和外部服务
- **Repository 层**：数据访问层，封装数据库和 Redis 操作
- **Model 层**：数据模型定义，GORM 模型

## 6. API 与契约

### 6.1 总则

- **统一前缀**：`/api/v1/certificates`
- **认证方式**：JWT Bearer Token
- **响应格式**：`{success: bool, code: int, message: string, data: object, error?: object}`
- **分页规则**：`page`、`page_size` 参数，返回包含 `items`, `total`, `page`, `page_size`, `total_pages` 字段的数据

#### 8.2.2 证书来源（certificate_source）

**设计说明**：将原 `certificate_type` 重构为 `certificate_source`，表示证书的获取方式。具体的 CA 提供商信息由 `ca_provider_id` 字段关联到 `ca_providers` 表，从而实现：
- **扩展性**：支持任意 ACME CA（Let's Encrypt、ZeroSSL、BuyPass、Google Trust Services 等）
- **清晰性**：来源方式和 CA 提供商职责分离
- **灵活性**：可动态添加新的 CA 提供商，无需修改枚举类型

| 代码         | i18n 键值                        | 描述                                 |
| ------------ | -------------------------------- | ------------------------------------ |
| acme         | certificate.source.acme          | 通过 ACME 协议自动申请获取（关联 ca_provider_id） |
| self_signed  | certificate.source.self_signed   | 平台生成的自签名证书（用于测试）     |
| uploaded     | certificate.source.uploaded      | 用户上传的第三方证书（商业 CA 购买） |

**示例场景**：
- Let's Encrypt 证书：`source=acme` + `ca_provider_id=1`（Let's Encrypt 记录）
- ZeroSSL 证书：`source=acme` + `ca_provider_id=2`（ZeroSSL 记录）
- 自签名证书：`source=self_signed` + `ca_provider_id=NULL`
- 商业证书上传：`source=uploaded` + `ca_provider_id=NULL`

| Google Trust Services | acme_eab | 仅付费 | 90天 | ✅ | https://dv.acme-v02.api.pki.goog/directory | Google 云集成，商业使用，需 EAB |

**证书产品类型说明**：
- **DV (Domain Validation)**：域名验证证书，免费/低成本，自动化验证
- **OV (Organization Validation)**：组织验证证书，需要验证企业身份，付费
- **EV (Extended Validation)**：扩展验证证书，最高级别验证，地址栏显示公司名，付费

**费用模型**：
- 免费证书：通常有频率限制（如 Let's Encrypt 每周 50 个证书）、有效期较短（90 天）
- 付费证书：更长有效期（1-2 年）、无频率限制、技术支持、企业 SLA、更高信任级别

**设计原则**：
- CA 提供商通过 `has_free_product` 和 `has_paid_product` 标识其产品线
- 每个申请的证书通过 `is_free` 字段明确标识是否免费
- 同一 CA（如 ZeroSSL）可以同时提供免费和付费证书

### 10.1 技术实现基础

**核心库**: [go-acme/lego](https://github.com/go-acme/lego) v4.x

**选择理由**：
- ✅ **成熟稳定**：Lego 是 Go 生态中最成熟的 ACME v2 客户端库，支持 RFC 8555 规范
- ✅ **CA 兼容性**：内置支持 Let's Encrypt、ZeroSSL、BuyPass 等主流 ACME CA
- ✅ **丰富的验证方式**：支持 HTTP-01、DNS-01、TLS-ALPN-01 三种验证方式
- ✅ **170+ DNS 提供商**：内置支持 170+ DNS 提供商的自动化验证（本版本暂不使用）
- ✅ **扩展性强**：提供清晰的接口，便于自定义 Provider 和挑战处理
- ✅ **证书管理**：支持注册、申请、续期、吊销完整生命周期

**核心接口封装**：

```go
// 平台封装层: internal/service/certificate_service.go
type CertificateService struct {
    legoClientFactory *LegoClientFactory
    repository        CertificateRepository
    caProviderService CAProviderService
    // ... 其他依赖
}

// Lego 客户端工厂
type LegoClientFactory struct {
    config   *lego.Config
    keyType  certcrypto.KeyType // RSA2048, RSA4096, EC256, EC384
}

// 基于 Lego 的核心操作
func (s *CertificateService) ApplyCertificate(ctx context.Context, req *ApplyCertRequest) (*Certificate, error) {
    // 1. 创建 Lego Client（根据 CA 配置）
    client, err := s.createLegoClient(req.CAProviderID)
    
    // 2. 注册 ACME 账户（首次）或加载已有账户
    account, err := s.getOrRegisterAccount(client, caProvider)
    
    // 3. 设置 Challenge Provider
    if req.ValidationMethod == "http-01" {
        client.Challenge.SetHTTP01Provider(s.newHTTP01Provider())
    } else if req.ValidationMethod == "dns-01" {
        client.Challenge.SetDNS01Provider(s.newManualDNS01Provider())
    }
    
    // 4. 使用 Lego 申请证书
    request := certificate.ObtainRequest{
        Domains: req.Domains,
        Bundle:  true, // 包含证书链
    }
    certificates, err := client.Certificate.Obtain(request)
    
    // 5. 保存证书到数据库（加密私钥）
    return s.saveCertificate(ctx, certificates, req)
}
```

- ✅ ACME 协议通信（nonce 管理、签名、重试机制）
- ✅ 账户注册与密钥管理
- ✅ 订单创建与授权管理
- ✅ 挑战协调与状态轮询
- ✅ CSR 生成与证书获取
- ✅ 证书续期逻辑（检测到期时间）
- ✅ 证书吊销 API 调用

**平台需要实现的部分**：
- 📋 Challenge Provider 接口实现（HTTP-01 文件托管、DNS-01 手动验证）
- 📋 证书元数据管理（数据库 CRUD）
- 📋 私钥加密存储（AES-256-GCM）
- 📋 续期任务调度（定时扫描到期证书）

### 10.2 证书申请流程（基于 Lego）

```
用户提交申请
    ↓
创建证书记录（status=pending）
    ↓
【Lego Client 创建】
    ├─ 加载/注册 ACME 账户
    ├─ 设置 Challenge Provider
    └─ 调用 client.Certificate.Obtain()
          ↓
      【Lego 内部自动处理】
          ├─ 创建 ACME 订单
          ├─ 获取授权挑战
          ├─ 调用平台的 Provider.Present()
          ├─ 通知 CA 验证
          ├─ 轮询验证状态
          ├─ 生成 CSR
          └─ 获取签发的证书
              ↓

    ├─ 加密存储私钥
```

**详细实现步骤**：

1. **用户提交申请**：验证域名格式、检查域名是否已有有效证书（可选）、验证 CA 提供商是否可用

2. **创建证书记录**：在 `certificates` 表中创建记录，状态为 `pending`

3. **初始化 Lego Client** - 包含错误处理和日志：
   ```go
   import (
       "api-service/internal/constants"
       "api-service/pkg/errors"
       "api-service/pkg/logger"
       "github.com/go-acme/lego/v4/lego"
       "github.com/go-acme/lego/v4/certcrypto"
   )
   
   func (s *CertificateService) createLegoClient(ctx context.Context, caProviderID uint) (*lego.Client, error) {
       // 获取 CA 提供商配置
       caProvider, err := s.caProviderRepo.GetByID(ctx, caProviderID)
       if err != nil {
           logger.ErrorContext(ctx, "Failed to get CA provider",
               logger.Uint("ca_provider_id", caProviderID),
               logger.ErrorField(err))
           return nil, errors.NewAppErrorWrapError(err, errors.CodeCAProviderNotFound)
       }
       
       if !caProvider.Enabled {
           logger.WarnContext(ctx, "CA provider is disabled",
               logger.Uint("ca_provider_id", caProviderID),
               logger.String("ca_name", caProvider.Name))
           return nil, errors.NewAppError(errors.CodeCAProviderDisabled)
       }
       
       // 创建 Lego Config
       config := lego.NewConfig(account)
       config.CADirURL = caProvider.DirectoryURL
       config.Certificate.KeyType = certcrypto.RSA2048
       
       client, err := lego.NewClient(config)
       if err != nil {
           logger.ErrorContext(ctx, "Failed to create Lego client",
               logger.String("directory_url", caProvider.DirectoryURL),
               logger.ErrorField(err))
           return nil, errors.NewAppErrorWrapError(err, errors.CodeInternalError)
       }
       
       logger.InfoContext(ctx, "Lego client created successfully",
           logger.String("ca_provider", caProvider.Name),
           logger.String("directory_url", caProvider.DirectoryURL))
       
       return client, nil
   }
   ```

   ```go
               map[string]interface{}{"ca_name": caProvider.Name},
           )
       }
       
       if !req.IsFree && !caProvider.HasPaidProduct {
           return nil, errors.NewAppErrorWithI18nParams(

               "certificate.paid_ca_required",
               map[string]interface{}{"ca_name": caProvider.Name},
           )
       }
       
       // 2. 创建 Lego Client
       client, err := s.createLegoClient(ctx, req.CAProviderID)
       if err != nil {
           return nil, err  // 错误已包装
       }
       
       // 3. 设置 Challenge Provider
       if err := s.setupChallengeProvider(ctx, client, req.ValidationMethod); err != nil {
           return nil, err
       }
       
       // 4. 申请证书
       request := certificate.ObtainRequest{
           Domains: req.Domains,
           Bundle:  true,  // 包含中间证书链
       }
       
       logger.InfoContext(ctx, "Requesting certificate from CA",
           logger.Strings("domains", req.Domains))
       
       certificates, err := client.Certificate.Obtain(request)
       if err != nil {
           logger.ErrorContext(ctx, "Failed to obtain certificate from CA",
               logger.Strings("domains", req.Domains),
               logger.String("ca_provider", caProvider.Name),
               logger.ErrorField(err))
           return nil, errors.NewAppErrorWrapError(err, errors.CodeCertificateObtainFailed)
       }
       
       logger.InfoContext(ctx, "Certificate obtained successfully from CA",
           logger.String("domain", certificates.Domain),
           logger.Int("cert_length", len(certificates.Certificate)))

       cert, err := s.saveCertificate(ctx, certificates, req)

           logger.String("primary_domain", cert.PrimaryDomain),
   ```

```go
func (p *ManualDNS01Provider) Present(domain, token, keyAuth string) error {
    ctx := context.Background()

        DNSRecordValue:  info.Value,

        logger.ErrorContext(ctx, "Failed to save DNS validation record",
            logger.String("domain", domain),

        return errors.NewAppErrorWrapError(err, errors.CodeDatabaseOperationFailed)

    logger.InfoContext(ctx, "DNS validation record saved",

        logger.String("domain", domain))

        logger.WarnContext(ctx, "Failed to clean up DNS validation record",
            logger.String("domain", domain),
            logger.ErrorField(err))
        // 不阻塞流程
    }

// DNS 记录检查 - 在用户点击"我已完成验证"后调用
func (s *CertificateService) CheckDNSRecord(
    ctx context.Context, 
    validationID uint,
) error {
    validation, err := s.validationRepo.GetByID(ctx, validationID)
    if err != nil {
        logger.ErrorContext(ctx, "Failed to get validation record",
            logger.Uint("validation_id", validationID),
            logger.ErrorField(err))
        return errors.NewAppErrorWrapError(err, errors.CodeRecordNotFound)
    }
    
    logger.InfoContext(ctx, "Checking DNS record",
        logger.String("domain", validation.Domain),
        logger.String("fqdn", validation.DNSRecordName),
        logger.String("expected_value", validation.DNSRecordValue))
    
    // 使用 dns01.PreCheckFunc 检查 DNS 记录
    checkFunc := dns01.PreCheckFunc(dns01.RecursiveNameservers, "8.8.8.8:53")
    if err := checkFunc(validation.DNSRecordName, validation.DNSRecordValue); err != nil {
        logger.ErrorContext(ctx, "DNS record verification failed",
            logger.String("fqdn", validation.DNSRecordName),
            logger.ErrorField(err))
        
        return errors.NewAppErrorWithI18nParams(
            errors.CodeDNSRecordNotFound,
            "certificate.dns_record_not_found",
            map[string]interface{}{
                "fqdn":  validation.DNSRecordName,
                "value": validation.DNSRecordValue,
            },
        )
    }
    
    // 更新验证状态
    validation.Status = constants.VALIDATION_STATUS_VALID
    validation.ValidatedAt = time.Now()
    if err := s.validationRepo.Update(ctx, validation); err != nil {
        logger.ErrorContext(ctx, "Failed to update validation status",
            logger.Uint("validation_id", validationID),
            logger.ErrorField(err))
        return errors.NewAppErrorWrapError(err, errors.CodeDatabaseOperationFailed)
    }
    
    logger.InfoContext(ctx, "DNS record verified successfully",
        logger.String("domain", validation.Domain),
        logger.String("fqdn", validation.DNSRecordName))
    
    return nil
}
```

**用户操作流程**：
1. 平台调用 Lego 申请证书（Lego 调用平台的 `Present()` 方法，记录日志）
2. 平台返回 DNS 记录信息给用户（通过 API 响应，包含 FQDN 和 Value）
3. 用户在 DNS 提供商控制台手动添加 TXT 记录
4. 用户点击"我已完成验证"按钮（调用 `CheckDNSRecord` API，记录验证日志）
5. 平台调用 `dns01.PreCheckFunc` 检查 DNS 记录是否生效（使用错误包装）
6. Lego 继续轮询 CA 验证状态，完成证书签发（记录成功日志）

```go
// 上传证书 - 符合项目规范
func (s *CertificateService) UploadCertificate(
    ctx context.Context,
    req *dto.UploadCertificateRequest,
    certFile, keyFile *multipart.FileHeader,
) (*model.Certificate, error) {
    logger.InfoContext(ctx, "Starting certificate upload",
        logger.String("name", req.Name),
        logger.Strings("domains", req.Domains))
    
    // 1. 验证文件大小
    if certFile.Size > files.MAX_UPLOAD_SIZE {
        return nil, errors.NewAppError(errors.CodeFileTooLarge)
    }
    if keyFile.Size > files.MAX_UPLOAD_SIZE {
        return nil, errors.NewAppError(errors.CodeFileTooLarge)
    }
    
    // 2. 读取证书文件
    certContent, err := files.ReadUploadedFile(certFile)
    if err != nil {
        logger.ErrorContext(ctx, "Failed to read certificate file",
            logger.String("filename", certFile.Filename),
            logger.ErrorField(err))
        return nil, errors.NewAppErrorWrapError(err, errors.CodeFileReadFailed)
    }
    
    // 3. 读取私钥文件
    keyContent, err := files.ReadUploadedFile(keyFile)
    if err != nil {
        logger.ErrorContext(ctx, "Failed to read private key file",
            logger.String("filename", keyFile.Filename),
            logger.ErrorField(err))
        return nil, errors.NewAppErrorWrapError(err, errors.CodeFileReadFailed)
    }
    
    logger.InfoContext(ctx, "Certificate files read successfully",
        logger.Int("cert_size", len(certContent)),
        logger.Int("key_size", len(keyContent)))
    
    // 4. 验证证书格式
    certBlock, _ := pem.Decode(certContent)
    if certBlock == nil || certBlock.Type != "CERTIFICATE" {
        logger.ErrorContext(ctx, "Invalid certificate format",
            logger.String("filename", certFile.Filename))
        return nil, errors.NewAppError(errors.CodeCertificateInvalidFormat)
    }
    
    x509Cert, err := x509.ParseCertificate(certBlock.Bytes)
    if err != nil {
        logger.ErrorContext(ctx, "Failed to parse certificate",
            logger.ErrorField(err))
        return nil, errors.NewAppErrorWrapError(err, errors.CodeCertificateInvalidFormat)
    }
    
    // 5. 验证私钥格式
    keyBlock, _ := pem.Decode(keyContent)
    if keyBlock == nil {
        logger.ErrorContext(ctx, "Invalid private key format",
            logger.String("filename", keyFile.Filename))
        return nil, errors.NewAppError(errors.CodePrivateKeyInvalid)
    }
    
    // 6. 验证证书和私钥是否匹配
    if err := s.validateCertKeyMatch(x509Cert, keyContent); err != nil {
        logger.ErrorContext(ctx, "Certificate and private key mismatch",
            logger.ErrorField(err))
        return nil, errors.NewAppError(errors.CodeCertificateKeyMismatch)
    }
    
    logger.InfoContext(ctx, "Certificate and private key validated successfully")
    
    // 7. 加密私钥
    encryptedKey, err := s.cryptoService.EncryptPrivateKey(keyContent)
    if err != nil {
        logger.ErrorContext(ctx, "Failed to encrypt private key",
            logger.ErrorField(err))
        return nil, errors.NewAppErrorWrapError(err, errors.CodeCertificateEncryptionFailed)
    }
    
    // 8. 提取证书信息
    domains := s.extractDomainsFromCert(x509Cert)
    
    // 9. 保存证书记录
    cert := &model.Certificate{
        Name:           req.Name,
        Domains:        domains,
        PrimaryDomain:  x509Cert.Subject.CommonName,
        Source:         constants.CERT_SOURCE_UPLOADED,
        Status:         constants.CERT_STATUS_ISSUED,
        CertificatePEM: string(certContent),
        EncryptedKey:   encryptedKey,
        IssuedAt:       x509Cert.NotBefore,
        ExpiresAt:      x509Cert.NotAfter,
        Description:    req.Description,
    }
    
    if err := s.repository.Create(ctx, cert); err != nil {
        logger.ErrorContext(ctx, "Failed to save uploaded certificate",
            logger.String("primary_domain", cert.PrimaryDomain),
            logger.ErrorField(err))
        return nil, errors.NewAppErrorWrapError(err, errors.CodeDatabaseOperationFailed)
    }
    
    logger.InfoContext(ctx, "Certificate uploaded successfully",
        logger.Uint("certificate_id", cert.ID),
        logger.String("primary_domain", cert.PrimaryDomain),
        logger.Strings("domains", cert.Domains))
    
    // 10. 记录审计日志

        "certificate_id": cert.ID,
        "domains":        cert.Domains,
        "expires_at":     cert.ExpiresAt,
    })
```

### 10.5 证书续期策略（基于 Lego）

```go
import (

// 定时任务：扫描即将到期的证书 - 符合项目规范
func (s *CertificateService) RenewExpiringCertificates(ctx context.Context) error {
    logger.InfoContext(ctx, "Starting certificate renewal check")
    
    // 查询 30 天内到期的证书
    thresholdDays := s.config.Certificate.Renewal.ThresholdDays
    certs, err := s.repository.FindExpiringCertificates(ctx, thresholdDays)
    if err != nil {

    }
    
    logger.InfoContext(ctx, "Found expiring certificates",
        logger.Int("count", len(certs)),
        logger.Int("threshold_days", thresholdDays))
    
    // 统计续期结果
    successCount := 0
    failedCount := 0
    
    for _, cert := range certs {
        if err := s.renewSingleCertificate(ctx, &cert); err != nil {
            logger.ErrorContext(ctx, "Failed to renew certificate",
                logger.Uint("certificate_id", cert.ID),
                logger.String("primary_domain", cert.PrimaryDomain),
                logger.ErrorField(err))
            failedCount++
        } else {
            successCount++
        }
    }
    
    logger.InfoContext(ctx, "Certificate renewal check completed",
        logger.Int("success_count", successCount),
        logger.Int("failed_count", failedCount))
    
    return nil
}

// 续期单个证书
func (s *CertificateService) renewSingleCertificate(
    ctx context.Context,
    cert *model.Certificate,
) error {
    logger.InfoContext(ctx, "Renewing certificate",
        logger.Uint("certificate_id", cert.ID),
        logger.String("primary_domain", cert.PrimaryDomain),
        logger.Time("expires_at", cert.ExpiresAt))
    
    // 1. 检查证书来源
    if cert.Source != constants.CERT_SOURCE_ACME {
        logger.WarnContext(ctx, "Certificate is not ACME-issued, skipping renewal",
            logger.Uint("certificate_id", cert.ID),
            logger.String("source", cert.Source))
        return nil
    }
    
    // 2. 创建 Lego Client
    client, err := s.createLegoClient(ctx, cert.CAProviderID)
    if err != nil {
        logger.ErrorContext(ctx, "Failed to create Lego client for renewal",
            logger.Uint("certificate_id", cert.ID),
            logger.ErrorField(err))
        return s.handleRenewalFailure(ctx, cert, err)
    }
    
    // 3. 使用 Lego Renew API
    renewReq := certificate.RenewalInfoRequest{
        Cert: []byte(cert.CertificatePEM),
    }
    
    logger.InfoContext(ctx, "Requesting certificate renewal from CA",
        logger.Uint("certificate_id", cert.ID))
    
    newCert, err := client.Certificate.Renew(renewReq, true, false)
    if err != nil {
        logger.ErrorContext(ctx, "Failed to renew certificate from CA",
            logger.Uint("certificate_id", cert.ID),
            logger.String("primary_domain", cert.PrimaryDomain),
            logger.ErrorField(err))
        return s.handleRenewalFailure(ctx, cert, err)
    }
    
    // 4. 加密新私钥
    encryptedKey, err := s.cryptoService.EncryptPrivateKey(newCert.PrivateKey)
    if err != nil {
        logger.ErrorContext(ctx, "Failed to encrypt renewed private key",
            logger.Uint("certificate_id", cert.ID),
            logger.ErrorField(err))
        return errors.NewAppErrorWrapError(err, errors.CodeCertificateEncryptionFailed)
    }
    
    // 5. 更新证书
    cert.CertificatePEM = string(newCert.Certificate)
    cert.ChainPEM = string(newCert.IssuerCertificate)
    cert.EncryptedKey = encryptedKey
    cert.IssuedAt = time.Now()
    cert.ExpiresAt = time.Now().AddDate(0, 0, 90) // 根据 CA 配置
    cert.LastRenewedAt = time.Now()
    cert.Status = constants.CERT_STATUS_ISSUED
    
    if err := s.repository.Update(ctx, cert); err != nil {
        logger.ErrorContext(ctx, "Failed to save renewed certificate",
            logger.Uint("certificate_id", cert.ID),
            logger.ErrorField(err))
        return errors.NewAppErrorWrapError(err, errors.CodeDatabaseOperationFailed)
    }
    
    // 6. 记录续期历史
    renewal := &model.CertificateRenewal{
        CertificateID: cert.ID,
        Status:        "success",
        RenewedAt:     time.Now(),
        NewExpiresAt:  cert.ExpiresAt,
    }
    s.renewalRepo.Create(ctx, renewal)
    
    // 7. 发送通知
    s.notificationService.Send(ctx, &notification.Message{
        UserID:  cert.CreatedBy,
        Title:   s.i18n.T(ctx, "certificate.renew_success"),
        Type:    "certificate",
        Data: map[string]interface{}{
            "certificate_id": cert.ID,
            "domains":        cert.Domains,
            "expires_at":     cert.ExpiresAt,
        },
    })
    
    logger.InfoContext(ctx, "Certificate renewed successfully",
        logger.Uint("certificate_id", cert.ID),
        logger.String("primary_domain", cert.PrimaryDomain),
        logger.Time("new_expires_at", cert.ExpiresAt))
    
    // 8. 记录审计日志
    s.auditService.Log(ctx, "certificate.renewed", map[string]interface{}{
        "certificate_id": cert.ID,
        "domains":        cert.Domains,
        "old_expires_at": cert.ExpiresAt.AddDate(0, 0, -90),
        "new_expires_at": cert.ExpiresAt,
    })
    
    return nil
}

// 处理续期失败
func (s *CertificateService) handleRenewalFailure(
    ctx context.Context,
    cert *model.Certificate,
    renewalErr error,
) error {
    logger.ErrorContext(ctx, "Handling certificate renewal failure",
        logger.Uint("certificate_id", cert.ID),
        logger.String("reason", renewalErr.Error()))
    
    // 记录续期失败历史
    renewal := &model.CertificateRenewal{
        CertificateID: cert.ID,
        Status:        "failed",
        ErrorMessage:  renewalErr.Error(),
        AttemptedAt:   time.Now(),
    }
    s.renewalRepo.Create(ctx, renewal)
    
    // 检查重试次数
    failedAttempts, _ := s.renewalRepo.CountFailedAttempts(ctx, cert.ID)
    maxRetries := s.config.Certificate.Renewal.MaxRetryAttempts
    
    if failedAttempts >= maxRetries {
        // 达到最大重试次数，发送告警
        logger.ErrorContext(ctx, "Certificate renewal failed after max retries",
            logger.Uint("certificate_id", cert.ID),
            logger.Int("failed_attempts", failedAttempts),
            logger.Int("max_retries", maxRetries))
        
        // 更新证书状态
        cert.Status = constants.CERT_STATUS_FAILED
        s.repository.Update(ctx, cert)
        
        // 发送告警通知
        s.notificationService.SendAlert(ctx, &notification.Alert{
            Level:   "error",
            Title:   "证书续期失败",
            Content: s.i18n.T(ctx, "certificate.renewal_failed", map[string]interface{}{
                "reason": renewalErr.Error(),
            }),
            Data: map[string]interface{}{
                "certificate_id":  cert.ID,
                "domains":         cert.Domains,
                "failed_attempts": failedAttempts,
            },
        })
    }
    
    return errors.NewAppErrorWrapError(renewalErr, errors.CodeCertificateRenewalFailed)
}
```

**续期策略说明**：
- 定期扫描（默认每 24 小时）即将到期的证书（默认 30 天内）
- 使用 Lego Renew API 自动续期
- 最多重试 3 次，重试间隔 6 小时
- 续期成功后发送通知，失败后发送告警
- 记录所有续期历史到 `certificate_renewals` 表

**加密流程说明**：
1. 生成 RSA 私钥后，调用 `pkg/crypto` 服务获取加密密钥
2. 使用 AES-256-GCM 加密私钥
3. 生成随机 IV，计算认证标签
4. 组装加密数据（IV + 密文 + 标签）
5. 存储到数据库 BLOB 字段

**解密流程说明**：
1. 从数据库读取加密数据
2. 解析 IV、密文和标签
3. 调用 `pkg/crypto` 服务获取解密密钥
4. 使用 AES-256-GCM 解密
5. 验证认证标签
6. 返回原始私钥PEM

**安全措施**：
- 加密密钥存储在独立的密钥管理服务
- 使用 AES-256-GCM 认证加密
- 日志中不记录私钥内容
- 解密操作需要特殊权限验证

#### 10.7.3 Controller 层错误处理示例

```go
import (
    "api-service/internal/dto/request"
    "api-service/internal/dto/response"
    "api-service/pkg/errors"
    "api-service/pkg/logger"
    "github.com/gin-gonic/gin"
    "net/http"
)

// 申请证书 API
func (c *CertificateController) ApplyCertificate(ctx *gin.Context) {
    var req request.ApplyCertificateRequest
    if err := ctx.ShouldBindJSON(&req); err != nil {
        logger.ErrorContext(ctx, "Failed to parse request",
            logger.ErrorField(err))
        
        ctx.JSON(http.StatusBadRequest, errors.NewAppError(
            errors.CodeInvalidRequest,
            "Invalid request parameters",
        ).WithDetails(map[string]interface{}{
            "error": err.Error(),
        }))
        return
    }
    
    // 调用 Service 层
    cert, err := c.service.ApplyCertificate(ctx, &req)
    if err != nil {
        // Service 层已经包装了 AppError，直接返回
        if appErr, ok := err.(*errors.AppError); ok {
            logger.ErrorContext(ctx, "Certificate application failed",
                logger.Int("error_code", int(appErr.Code)),
                logger.String("error_message", appErr.Message),
                logger.ErrorField(err))
            
            ctx.JSON(appErr.GetHTTPStatus(), appErr)
            return
        }
        
        // 未知错误
        logger.ErrorContext(ctx, "Unexpected error",
            logger.ErrorField(err))
        ctx.JSON(http.StatusInternalServerError, errors.NewAppErrorWrapError(
            err,
            errors.CodeInternalServerError,
        ))
        return
    }
    
    // 成功响应
    ctx.JSON(http.StatusOK, response.NewSuccessResponse(cert))
}
```

### 15.2 ACME 协议简介

ACME（Automatic Certificate Management Environment）是一个通信协议，用于自动化证书管理。Let's Encrypt 是最知名的 ACME CA。

**ACME 工作流程**：

1. 账户注册：向 CA 注册 ACME 账户
2. 创建订单：为域名创建证书订单
3. 授权验证：完成域名所有权验证（HTTP-01 或 DNS-01）
4. 证书签发：验证通过后，CA 签发证书
5. 证书续期：到期前重复上述流程

**验证方法对比**：

| 验证方法 | 优点 | 缺点 | 适用场景 |
| -------- | ---- | ---- | -------- |
| HTTP-01 | 自动化程度高，无需手动操作 | 需要服务器可从公网访问 80 端口 | 公网可访问的 Web 服务 |
| DNS-01 | 支持通配符证书，不需要开放端口 | 需要 DNS API 或手动添加记录 | 内网服务、通配符证书 |

**Let's Encrypt 限制**：

- 每个注册域名每周最多 50 个证书
- 每个证书最多 100 个域名
- 证书有效期 90 天
